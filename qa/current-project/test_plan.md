# 芊浔民宿当前项目测试计划

## Feature scope / 功能范围

按当前仓库 V3.1 基线检查小程序用户和后台管理员的关键业务路径：手机号登录、房间查询与日期可订校验、预支付和模拟支付、后台订单处理、第三方订单创建、后台月历、会员新增和积分发放、支出与经营报表，以及取消退款和权限边界。接口契约参考 `docs/03-接口契约/芊浔民宿_接口设计文档_V3.1_20261118.md`。

报表专项使用多状态混合样本，核对 `ALL`、`NOT_CHECKED_IN`、`CHECKED_IN`，跨月订单与分币尾差，平台手续费和两类达人提成，取消单排除，停用渠道/达人历史分组保留，封房后入住率分母，以及全店利润、房间利润和空月份零值。

本轮使用 Spring Boot `MockMvc` 走 HTTP 控制器边界；涉及持久化和并发的 API 集成测试使用 Testcontainers 启动临时 MySQL 8。前端执行后台生产构建和小程序 TypeScript 检查。没有接入微信开发者工具或浏览器自动化，因此不把页面点击、微信运行时兼容性或真实设备表现计作已验证项。

## Module breakdown / 模块拆分

| 模块 | 主要检查内容 |
|---|---|
| 认证与权限 | 小程序/管理员登录、token 角色隔离、未授权访问 |
| 客房与房态 | 房间查询、日期边界、订单/封房/有效锁房合并、后台月历状态 |
| 下单与支付 | 10 分钟锁房、模拟支付建单、重复支付、超时关单、并发争房 |
| 后台订单 | 第三方订单创建、状态推进、冲突和平台单号防重、金额快照、并发订单号 |
| 会员与积分 | 管理员建会员、手机号去重、赠送/历史积分流水、订单奖励归属和幂等 |
| 退款 | 取消资格、18:00 边界、退款幂等、跨会员隔离、失败回滚 |
| 支出与报表 | 支出创建/不可变、概览/渠道/达人/客房维度、跨月分摊、利润和入住率 |
| 前端静态质量 | 管理后台生产构建、小程序 TypeScript 类型检查 |

## Test objectives / 测试目标

1. 验证用户从查询房间到锁房、模拟支付并在后台形成待确认订单的主流程。
2. 验证管理员能创建和推进订单、从房态日历确认每日房态、录入第三方订单并防止超售。
3. 验证会员和积分流水与余额一致，重复请求不会重复建单、扣分或发分。
4. 验证经营报表展示不同状态范围和渠道/达人/客房维度，并按住宿夜晚归属月份分摊。
5. 验证关键日期边界、金额不可变、权限隔离和事务失败回滚。

## Test strategy / 测试策略

- **Unit Test / 单元测试：** 检查会员等级门槛、订单取消资格、报表跨月分币尾差/入住率、支出日期汇总和金额格式。
- **API Test / 接口测试：** 通过 `MockMvc` 请求 `/api/app/**` 与 `/api/admin/**`，断言 HTTP 状态、统一响应字段、分页/视图数据、参数校验及身份权限响应。重点 API 包含 `/api/app/rooms/**`、`/api/app/payments/**`、`/api/admin/orders/**`、`/api/admin/room-calendar`、`/api/admin/members/**`、`/api/admin/members/{id}/points/grant`、`/api/admin/reports/**`。
- **Integration Test / 集成测试：** 使用临时 MySQL 8 执行迁移、Mapper/XML、事务和数据持久化断言；覆盖订单生命周期、会员积分流水、支出与报表。
- **Statistics reconciliation / 统计对账：** 同一数据集分别请求概览、渠道、达人、客房和仪表盘接口，逐项核算数量、夜数、实付、三类费用、净额、支出、利润和入住率。
- **Boundary Test / 边界测试：** 检查退房日可再入住、未来 60 日窗口、18:00 整不可取消、跨月间夜、分币尾差、空房入住率分母为零。
- **Negative Test / 负向测试：** 检查无 token/错误角色、非法日期和金额、订单间夜冲突、重复平台订单号、非法状态推进及不可变字段修改。
- **Idempotency Test / 幂等测试：** 检查重复模拟支付、退款/取消、积分奖励重试和手机号重复建会员。
- **Concurrency Test / 并发专项：** 检查同房同夜的并发支付预占、第三方订单并发建单、封房竞争及订单号唯一性。
- **Frontend checks / 前端检查：** `frontend/admin` 执行 `npm run build`；`frontend/miniprogram` 执行 `npm run typecheck`。未运行 UI 自动化或微信开发者工具真机/模拟器。

## Environment and execution / 环境与执行

- Java 21、Maven 3.9.4、Docker Desktop、Testcontainers MySQL 8。
- 后端全量命令：`mvn test`（工作目录 `backend/`）。
- 后端新增/修改断言复跑：`mvn '-Dtest=AvailabilityApiIntegrationTest,ExpenseReportApiIntegrationTest' test`（工作目录 `backend/`）。
- 前端命令分别在 `frontend/admin/`、`frontend/miniprogram/` 执行。
- 测试使用容器内临时数据库和测试凭据，不连接项目外部服务或生产数据。
- 对前端统计卡片进行代码路径静态核查；仓库没有现成的管理后台组件测试/浏览器 E2E 框架，因此未伪称页面自动化通过。
