## Findings / 统计检查发现

1. **确认的管理首页展示缺项：** V3.1 要求经营总览分开展示“未入住订单营业额”和“已入住订单营业额”。后台接口及类型均提供这两个值，但首页月视图只展示一张总营业额卡，将两个值相加后显示；页面没有分别展示两类营业额。相关代码见 [home/index.vue](../../frontend/admin/src/views/home/index.vue) 的 `summaryCards`。
2. **日视图入住率口径需确认：** 月度入住率由后端按已入住/已完成间夜计算，符合 V3.1。首页日视图则用所有有订单的房间数（包含待确认、待入住）除以可售房间数并标为“入住率”；V3.1 写明“不计算预订占用率”，该日视图口径与此可能冲突。建议把日视图称为“预订占用率”，或按已入住/已完成订单计算；需按既定需求口径决定。

## Risk analysis / 风险分析

- 本轮没有通过真实浏览器或微信开发者工具模拟完整页面点击，因此导航、表单交互、加载/错误态、图片资源、微信运行时兼容性及低端机表现仍需 UI 验收。
- MockMvc 在 Spring 测试进程内模拟 HTTP，不覆盖部署后的 Nginx 路由、TLS、跨域、代理头和生产配置。
- 未进行压力、长时间运行或生产容量测试；本轮并发检查只覆盖测试列出的关键订单、支付和封房竞争路径。
- 模拟支付/退款验证的是第一期本地业务账本，不代表真实微信资金流或支付渠道对账。
