# 商城功能测试计划

## 测试对象

- 提交：`6f65d3d feat:增加商城功能`
- 目标：验证管理员管理商品（创建、修改、上/下架）、会员购买（浏览、试算、预支付、模拟支付）到管理员发货、会员查看物流、管理员完成订单的闭环。
- 运行环境：Java 21、Spring Boot、MockMvc、JUnit 5、Testcontainers MySQL 8、Docker Desktop；支付配置为模拟支付，不调用真实微信服务。

## 功能范围

1. 管理员商品管理：列表、创建、修改、上架、下架。
2. 会员购买：仅查看上架商品、预支付快照、积分抵扣、模拟支付、默认收货信息。
3. 订单履约：管理员订单列表/详情、填写快递公司与单号、发货、完成订单、奖励积分。
4. 订单可见性：会员仅能查询自己的支付单、订单与退款；物流信息在会员订单列表可见。
5. 异常与一致性：认证、角色隔离、参数校验、商品下架、非法状态、重复操作、退款、并发请求、超时支付和积分预占。

## 模块拆分

| 模块 | 主要接口/组件 | 测试重点 |
|---|---|---|
| 商品 | `/api/admin/mall/products`、`/api/app/mall/products` | 上下架可见性、修改、分页、输入校验 |
| 支付 | `/api/app/mall/payments` | 服务端金额快照、积分、支付单所有权、模拟支付幂等、超时 |
| 商城订单 | `/api/app/mall/orders`、`/api/admin/mall/orders` | 身份边界、发货状态机、物流回显、完成奖励 |
| 退款 | `/api/app/mall/orders/{id}/refund` | 待发货退款、重复退款、退款与发货互斥、积分返还 |
| 前端 | 管理后台、微信小程序 | 后台构建、小程序类型检查、商城 API 类型适配 |

## 测试目标

- 证明在真实 MySQL 事务下，成功支付只生成一笔商城订单，管理员可以发货，会员能看到快递信息。
- 验证商品、支付、订单、积分及物流快照在状态变迁中的一致性。
- 验证未登录、错误角色、跨会员访问、非法输入和非法状态都得到正确 HTTP 错误响应及统一结构。
- 验证重复支付、重复发货、重复完成、退款及并发状态变更不会重复建单、重复奖励或造成错误状态。

## 测试策略

### Unit Test

复用并执行现有商城单元测试，覆盖商品服务、积分余额、微信预支付/退款适配与请求日志脱敏。

### API Test

新增 `MallPurchaseShipmentApiIntegrationTest`，通过 MockMvc 调用真实 HTTP 路由，覆盖管理员商品维护、会员购买、管理员发货/完成、用户物流回显、401/403/404/409/422/400 和统一响应结构。

### Integration Test

所有商城主链路使用 Testcontainers MySQL 8 和 Flyway 迁移执行；验证数据库行锁、订单状态、积分流水、默认收货信息、商品快照和订单号。

### Boundary Test

覆盖分页下界、数量为零、积分不足、空白商品名、空白快递资料、下架商品、未发货直接完成和不存在资源。

### Negative Test

覆盖未认证、会员访问后台、管理员访问会员接口、跨会员支付单/退款访问、退款后发货、过期模拟支付。

### Idempotency Test

覆盖同一支付单重复模拟支付、重复退款、重复完成、并发发货和并发完成；额外记录预支付 API 缺少调用方幂等键的风险，不能以“同一支付单”幂等替代“同一购买意图”幂等。

## 非本次实测范围

- 真实微信支付/退款、微信回调签名和公网回调联调：缺少商户配置、真实支付凭据与可达回调环境。
- 微信开发者工具中的视觉/交互 E2E：本次执行小程序 TypeScript 检查，未连接真实微信开发者工具。
- 压力、容量和长时间稳定性测试。
