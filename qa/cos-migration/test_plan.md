# COS 切换测试计划

## 测试范围

覆盖商城图片上传到 COS、旧客房图片引用、公开和签名地址、分片上传、初始化商品数据迁移，以及本地数据库的历史图片访问。测试不重启或部署现有服务，也不修改业务数据。

## 模块与目标

- 商城：`POST /api/admin/mall/products/images` 的身份权限、图片校验、统一响应、COS 失败处理与重复上传。
- 存储：配置缺失、地址编码、临时签名、简单上传、分片成功及失败中止。
- 数据：MySQL 8 Flyway V22、商品初始化图片及现有房间/商品图片引用。
- 客户端：管理后台构建、小程序类型检查；实际微信真机需另行执行。

## 测试策略

- **Unit Test**：JUnit 与 Mockito，验证图片类型、COS URL/签名、分片和异常，不调用真实云。
- **API Test**：MockMvc、真实安全过滤链、模拟 COS，验证上传接口的响应和鉴权。
- **Integration Test**：Docker Testcontainers MySQL 8，验证初始化迁移、商城与房间回归。
- **Boundary Test**：空文件、错误格式、8 MiB 分片边界、无效签名有效期和未配置 COS。
- **Negative Test**：匿名/会员权限、COS 服务异常、无效内容与不完整流。
- **Idempotency Test**：重复上传按现有实现产生两个独立对象；接口没有去重约定，不将其认定为幂等。
- **真实环境只读检查**：对当前本地数据库的图片链接请求 HEAD；此前曾对 71 条旧地址与 COS 对象逐条计算 SHA-256。HEAD 不证明页面内嵌预览、缓存行为或其他环境数据。
