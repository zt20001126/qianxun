## 重新实施说明

原实现提交为 `0c89fc2`（微信登录增加 OpenID），本次撤回该提交的代码和契约变更，保留本文供后续实现参考。实现前需核对当前仓库及业务基线、微信小程序主体认证、手机号授权权限及相关平台规则；不能仅以本文或历史提交认定条件已经满足。此前自动化测试曾通过，但撤回后不代表当前版本或未来重新实现已经通过，须重新执行本文的验收测试。生产环境中，直接手机号登录存在账号冒用风险，未完成安全身份验证前不应将其视为安全登录方案。

## 1. 已确认目标和边界

- 会员通过微信授权手机号登录；服务端从微信获取手机号和本小程序 OpenID，安全绑定后签发 30 天会员 JWT。
- 管理员预建的会员按微信验证手机号关联原会员，保留 ID、订单、积分和成长积分；手机号不存在时创建会员。
- 会员与 OpenID 一对一。已被其他微信绑定或 OpenID 属于其他会员时拒绝，不自动换绑，提示联系管理员线下核实；本次不提供解绑定或换绑接口。
- 后续支付不再要求手机号授权，每次通过 `wx.login` 取得的一次性凭证，由后端换取当前 OpenID 并与已绑定身份比对；禁止信任客户端提交的 OpenID。
- 停用仅输入手机号即可登录，旧会员 JWT 全部失效并重新登录；管理员 JWT 不受此次会员令牌版本限制。
- 不修改服务器代码，代码在本地完成，由用户推送部署；不调用真实扣款进行自动化测试。

## 2. 当前实现与问题

- `frontend/miniprogram/pages/login/index.ts`、`index.wxml` 和 `services/auth.ts` 将输入手机号直接提交 A01。
- `backend/src/main/java/com/qianxun/homestay/modules/auth/service/impl/AuthServiceImpl.java` 按手机号 upsert 并签发会员 JWT，未校验手机号归属。
- `WechatIdentityServiceImpl` 在支付时同时通过微信换取 OpenID 和手机号；`WechatIdentityBindingServiceImpl` 对会员行加锁并检查冲突。
- `WechatPaymentServiceImpl` 预支付时要求 `login_code`、`phone_code`；`frontend/miniprogram/pages/payment/index.wxml` 的支付按钮绑定 `getPhoneNumber`。
- `JwtServiceImpl` 当前以同一签名密钥签发两种角色令牌，旧会员令牌无认证版本；不能仅依靠更新小程序或清除本地存储让旧令牌失效。
- `members` 已有手机号唯一索引与可空、唯一 OpenID；`MemberServiceImpl.createMember` 支持管理员按手机号预建会员。

## 3. 目标流程和安全设计

### 3.1 登录与绑定

1. 用户阅读协议后，在登录页触发微信手机号授权，并通过 `wx.login` 获取一次性登录 code。是否保留手机号输入框作为辅助展示不影响安全：如保留，输入值只用来与微信返回手机号比对，不能作为认证依据。
2. 前端发送 `login_code`、`phone_code` 到登录接口；服务端分别向微信换取 OpenID 和 `purePhoneNumber`，校验微信响应及手机号格式；一次性 code、会话密钥、OpenID 和手机号不写日志。
3. 网络调用在数据库事务外完成；专用事务入口根据已验证手机号查找或创建会员并加锁，核对 OpenID 所有权与现有绑定，再绑定并签发令牌。并发创建或绑定依靠现有唯一索引、行锁、条件更新和重复键处理保证一致；不得使用可能因 OpenID 唯一键冲突而更新其他用户资料的宽泛 upsert。
4. 已有同号未绑定会员复用原 ID；已绑定相同 OpenID 幂等登录；冲突返回 409，其他会员数据不变。微信错误、拒绝授权、失效或重复 code 均不能签发令牌。

### 3.2 令牌切换

- 在 `JwtServiceImpl` 为新会员 JWT 增加固定的认证版本 claim，解析会员 JWT 时强制校验该版本，旧会员 JWT 缺少或版本不匹配返回 401。管理员 JWT 保持现有逻辑。由服务端强制执行，覆盖所有受保护会员接口；前端遇 401 清理会话并回到登录页。
- 使用安全版本切换与身份绑定共同保护会员数据；登录改造适用于真实和模拟支付模式，不能因为 `WECHAT_PAY_ENABLED=false` 就保留不安全的手机号登录。模拟支付只切换支付渠道，仍需要配置小程序身份验证所需 AppID/AppSecret 和微信授权能力。
- 现有会员不批量填充 OpenID；上线后首次通过授权手机号绑定。旧客户端请求格式不再兼容，需要协调升级。

### 3.3 微信支付

`wx.login` → 会员 JWT + `login_code` → 后端换取当前 OpenID → 读取当前会员绑定的 OpenID 并比较 → 验证本人待支付锁房和状态 → 微信预支付。缺绑定、身份不一致或微信凭证无效时拒绝，不调用微信下单；支付通知验签、金额及付款人核对和结算幂等规则不变。

## 4. 接口与数据库影响

| 接口 | 处理 | 契约和兼容性 |
| --- | --- | --- |
| `POST /api/app/auth/login` | 修改 | 请求由 `{phone}` 改为 `{login_code, phone_code}`；响应保留既有 token、有效期、会员资料结构。仅手机号请求不再签发令牌，返回 400；授权冲突 409，微信调用失败按现有业务错误规范处理。需同步客户端，旧版不兼容。 |
| `GET /api/app/auth/me` | 路径及响应不变 | 旧会员 JWT 返回 401；新令牌正常访问。 |
| `POST /api/app/payments/{payment_no}/wechat-prepay` | 修改 | 请求只需 `{login_code}`；后端验证已绑定 OpenID。忽略旧 `phone_code` 是否允许需严格按最终 DTO 校验策略落实，但不得将其作为授权依据；旧客户端能否继续运行不作承诺。 |
| `POST /api/admin/members` | 保持不变 | 管理员按手机号预建会员，后续微信授权匹配同一记录。 |
| 其他会员 API | 路径、业务契约不变 | 旧会员令牌统一失效；管理员 API 不受会员认证版本影响。 |
| 微信支付/退款回调 | 保持不变 | 仍按现有签名、金额和幂等规则处理。 |

数据库：`members.phone`、`members.openid` 及其唯一索引均复用；`orders.member_id`、积分表和其他业务表不变。不新增表、列或 Flyway 迁移；现有 NULL OpenID 首次安全登录时绑定，不做后台批量回填。订单及积分不复制、不转移。上线前检查现有数据一致性，绑定冲突人工处理；不要运行覆盖或破坏性 SQL。

## 6. 实施顺序与验收

1. **契约及测试基线**：同步登录和支付请求、旧 JWT 失效与绑定冲突规则。验收：文档明确接口输入、错误及版本兼容，不宣称手机号直接登录安全。
2. **身份换取和事务绑定**：拆分微信调用；复用唯一索引和锁绑定管理员预建或新建会员。验收：同号已有会员 ID/积分不变；重复绑定幂等；不同微信冲突和并发只成功一个；失败不签发 Token。
3. **JWT 版本**：会员新令牌带认证版本，旧令牌访问会员 API 返回 401；管理员令牌正常。验收包括缺 claim、伪造、过期、旧版与管理员角色。
4. **预支付**：只收 `login_code`，服务端比对当前与已绑定 OpenID；支付锁、金额和通知处理沿用。验收：相同用户可下单；缺绑定、不同 OpenID、非本人订单、过期锁房均不调用微信预支付。
5. **小程序**：登录页授权后发送两个 code；支付页仅调用 `wx.login`；401 清除会话。验收：管理员预建手机号第一次登录复用账号，支付不再弹手机号授权；拒绝授权或网络错误有明确提示。
6. **部署与回归**：运行 Java 编译、单元和 MySQL 8 集成测试、小程序类型检查及真机验收；提供旧版小程序不可用及重新登录通知。仅用户自行推送服务器。

## 7. 测试及发布

- 自动化：Mockito/微信 HTTP stub 覆盖成功、失效 code、微信故障、手机号缺失及非法；真实 MySQL 8 测试管理员预建、冲突、重复和并发；MockMvc 测登录、旧令牌拒绝、权限及预支付；测试真实付款回调的既有验签与幂等回归。不得使用真实商户密钥或真实扣款。
- 前端：`npm --prefix frontend/miniprogram run typecheck`；微信开发者工具和真机验证授权、拒绝、旧会话清理、支付时不重复手机号授权。
- 发布：先备份并部署后端及配置，再上传更新小程序；旧版会失去登录能力，需计划停机或同步发布窗口。新旧 JWT 安全版本阻止旧会员会话绕过；不要让后端混跑新旧安全逻辑。微信支付可暂关闭，但微信身份登录仍需要微信服务。
- 回滚：回滚旧后端会重新接受旧手机号登录和旧 JWT，有安全回退风险；不能直接回滚而不评估，应先暂停会员访问或采用经验证的安全回退方案。不得以回滚为由自动重绑或覆盖会员数据。
- 小程序手机号授权能力、隐私保护指引、调用额度与合法请求域名由平台配置；当前公网 IP 调试不能证明体验版/正式版满足要求。真实支付、退款与回调必须另行受控验收。
- 新的微信身份登录与 V3.1 手机号直接登录及 V3.2 支付时绑定存在明确变更；以本次用户确认的方案为准，实施时同步相关专项文档。
