# 腾讯云 COS 与阿里云 OSS 并行接入方案

> 日期：2026-11-27；状态：待审阅。本文为方案，不代表代码已经实现或云端联调通过。

## 目标与范围

新增独立的腾讯云 COS 后端能力，保留阿里云 OSS 依赖、配置和所有现有业务调用。现有商城上传仍写 OSS，房间旧地址仍按原逻辑解析；不切换生产流量、不迁移图片、不修改线上数据。COS 先由自动化测试和可选的人工集成测试调用，不开放新的 HTTP 接口。

本方案的非阻塞假设：首阶段提供后端上传与私有对象短期签名读取能力，供后续业务接入；目前没有界面入口或业务自动调用 COS。公有图片使用对象公开 URL，实际公有权限由云端配置决定，不由代码自动修改 ACL。若仅需公开图片，私有签名能力可以从实施范围移除。

## 现状及风险

- `backend/src/main/java/com/qianxun/homestay/modules/mall/service/impl/MallProductImageUploadServiceImpl.java` 使用阿里云 SDK，返回公开图片 URL。
- `backend/src/main/java/com/qianxun/homestay/modules/room/service/impl/RoomImageUrlServiceImpl.java` 将 `oss://` 解析为阿里云短期签名地址，对 HTTP(S) 地址直接返回。
- `backend/src/main/java/com/qianxun/homestay/config/OssProperties.java`、`backend/src/main/resources/application.yml` 和 `deploy/docker-compose.yml` 配置阿里云；`backend/pom.xml` 引入 OSS SDK。
- `backend/src/main/resources/db/migration/V17__seed_silk_quilt.sql`、`V18__replace_silk_quilt_images.sql` 和 `frontend/miniprogram/pages/around-guide/index.ts` 包含阿里云地址。运行中数据库、实际文件数量和对象权限未核实。
- 截图中的桶为 `qianxun-1536638067`，用户提供的上海域名下测试图片可匿名访问；这不证明全部对象公开或应用已有上传权限。

## 拟采用的结构和流程

保留两套供应商配置。COS 作为独立基础设施服务，仅负责指定对象键的上传、生成公开对象 URL、生成限时签名读取 URL；调用方负责业务权限、文件类型校验和决定是否公开。SDK 使用腾讯云官方 Java SDK，版本实施时核验并固定；不替换阿里云 SDK。上传失败要抛出明确异常，不自动回退或双写，以免出现来源不明的文件。

```text
现有商城接口 -> 现有 OSS 上传服务 -> 阿里云（不变）
现有房间接口 -> 现有 OSS 图片解析 -> 阿里云（不变）
测试 / 未来调用方 -> COS 服务接口 -> COS 实现及 SDK -> 腾讯云（独立）
```

COS 未配置时，应用仍可启动且原业务不受影响；仅在显式调用 COS 能力时检查配置并返回可理解的错误。密钥不进入仓库、客户端、响应或日志；应用使用受限的 CAM 子账号权限，生产环境按实际操作授予。

## 接口与数据库影响

无 HTTP API 新增或修改。`POST /api/admin/mall/products/images` 的请求、返回、鉴权和 OSS 写入保持不变；`GET /api/app/rooms`、`GET /api/app/rooms/{id}` 的图片行为保持不变。新服务只供后端内部调用，不能用现有上传接口验证 COS。

无数据库结构或数据变更：`room.images`、`mall_product.images` 保持现有内容；不修改已应用的 Flyway 文件，不回填地址。前端、微信域名设置、云端权限和既有对象均不在本次自动改动范围。

## 实施步骤与验收

1. **引入配置及 SDK**：修改 `pom.xml`、`application.yml`、`docker-compose.yml`、`.env.example`，新增 `CosProperties`。验收：两家配置独立，COS 空配置下应用初始化不触发云端访问；SDK 固定版本可编译。
2. **实现 COS 服务**：新增接口与实现。验收：有效配置可按指定键上传并生成 URL；中文、空格、斜杠等对象键编码正确；私有签名存在明确到期时间；配置缺失及 SDK 故障有明确失败，不回退或泄露密钥。URL 不能作为权限变更的证据。
3. **自动化验证**：新增服务测试，覆盖成功、缺参、上传故障、特殊字符及签名有效期；运行现有商城上传测试和相关房间回归测试，并检查未配置 COS 的上下文启动。验收：上述测试通过，原 OSS 配置及业务链路未改变。
4. **可选真实 COS 联调**：由部署者安全配置限定权限的测试凭据和测试对象，执行单独的、显式启用的集成测试；验证上传后内容、公开测试对象的匿名访问及私有对象签名有效/过期。测试数据使用独立前缀，清理须具备相应授权；未经授权保留并记录测试对象。缺少凭据时明确标记未执行，不将 mock 成功视作云端联调成功。

计划运行 `mvn -s backend/maven-settings/aliyun.xml -f backend/pom.xml test` 及必要编译检查；若集成测试依赖 Docker 或凭据而不可用，单独报告。本文中的测试均为计划，尚未执行。

## 将来切换时另行实施

切换需要清点阿里云文件及数据库、代码中的地址；保持对象键并校验内容与权限，检查小程序合法域名；先验证新上传，再通过新增迁移或受控操作更新已核实的历史引用。保留旧 OSS 文件、凭据及解析代码，直至验证与回退期结束。不得直接更改已执行迁移。切换涉及现有业务行为与文档，需单独明确范围和验收。
