# 智能体通用工具机制与今日营业数据查询方案（待审阅）

## 目标和现状

完善一次通用工具调用机制，使后台智能体可以发现、调用已注册工具，并按工具结果继续回答或等待用户输入；在此基础上增加今日营业数据工具。后续新增同类查询工具只需实现约定的接口并注册，原则上不修改模型适配器、工具分发器或对话主流程。此次只制定方案。

现有 AgentServiceImpl.chat 将所有工具调用转为题卡等待；ToolNode 只识别 ask_user_questions；DeepSeekModel 将工具定义写死在请求中；AgentModelMessage 只含 role 和 content，无法表达工具调用及关联结果。ReportService.dashboard 返回当日房态和月度金额；截图的当日金额在前端 home/index.vue 的 calculateDailyFinance 中计算，后端尚无可直接调用的完整日汇总。

## 一、一次性完善通用工具调用机制

### 职责与流程

- 定义统一工具接口：每个工具提供唯一名称、模型可理解的描述、参数 JSON Schema，以及执行方法。执行方法负责服务端参数校验，不信任模型传入的数据。
- Spring 自动收集实现接口的组件构成注册表：启动时检查工具名唯一；模型请求使用同一注册表生成工具列表；工具节点按名称从同一注册表查找执行。未知工具明确报错。
- 定义两种执行结果：普通结果回传模型，由模型继续生成；需要用户回答的题卡结果结束本轮并返回 waiting。对话流程按结果类型处理，不按具体工具名称判断。保留现有题卡校验和回答流程。
- 模型协议保留 assistant 的工具调用、原始参数与工具调用 ID，将匹配 ID 的 tool 结果加入同一轮完整上下文，继续调用模型。保留现有单次一个工具调用限制，多工具调用明确失败；设置单轮调用次数上限，避免无限循环。
- 不引入新的智能体框架或持久化工具调用记录。只允许后台已认证管理员通过既有会话入口使用工具；返回给模型的数据由工具控制。网络请求仍在数据库写事务外，维持会话并发检查。

## 二、新增今日营业数据工具

### 调用关系和口径

管理员提出“今日营业情况” → 模型选择 get_today_business_data → 注册表查找并执行 TodayBusinessDataTool → 注入的 ReportService 查询当日汇总 → 汇总结果回传模型 → 智能体回答。

工具不接收日期或其他业务参数；服务端一次性按 Asia/Shanghai 获取当天日期。返回日期、总房数、占用、空房、入住率、营业额、平台手续费、平台达人提成、达人额外提成和商家到手金额，金额为两位小数的十进制字符串。仅传汇总，不传顾客姓名、电话或订单明细。失败时提示无法查询，不返回伪造的零。

拟复用 ReportMapper.findDashboardRooms 和 findMonthOrders，以及 ReportServiceImpl.allocate；在报表服务只读事务内筛选覆盖当晚且未取消的订单，对每个订单逐项按住宿晚数分摊并汇总。无需查询 Controller、HTTP 自调用、重复 SQL 或调用订单详情接口。

建议沿用现有日看板展示口径：占用包括订单占房和封房；空房为总房数减占用；日入住率为订单占房数除以总房数减封房数，分母不大于零显示 0.0%。包括待确认、待入住订单。正式月报入住率仅包含已入住/已完成且零分母为 null，回答应标明日看板口径。金额分别将订单实付、各项费用及净额按晚分摊，分币尾差归最后一晚，与截图一致；因此某一日单独分摊后的净额可能与该日实付减费用相差几分钱，不应用月报净额计算替代。这两个差异是待审阅的业务口径，实施前须确认继续沿用截图。

## API、数据库和前端影响

- POST /api/admin/agent/chat：路径、请求和响应字段不变，新增通过自然语言查询营业数据的行为，保留 completed / waiting。
- GET /api/admin/agent/conversations、GET /api/admin/agent/conversations/{id}/messages、GET /api/admin/dashboard：不变；不新增公开 API。
- room、room_block、orders、order_amount、channels 仅使用现有查询；会话与消息表维持现状；不新增或修改表、字段、索引，不需要迁移和回填。
- 不修改管理后台页面及现有日看板计算；新业务方法仅在后端内部调用。与截图的一致性由边界测试验证。

## 实施顺序和验收

1. 通用注册：新增接口、注册表、结果类型，将现有提问工具接入。验收：通过测试组件增加工具后，工具自动出现在模型定义且可通过名称执行；重复名称和未知工具明确报错。
2. 对话协议和编排：改造模型消息及查询结果回传。验收：带正确调用 ID 的结果进入下一次模型请求；普通工具生成 completed，提问仍返回 waiting；错误、超限、并发冲突有明确处理。
3. 今日业务：新增报表日汇总、VO 和工具。验收：相同数据下，截图各项结果一致；取消订单排除、退房日不计、跨月及最后一晚尾差正确，封房和空数据符合日看板；回答含日期且不泄露顾客数据。
4. 运行报表及智能体相关测试和后端编译。覆盖非法参数、失败、权限、旧题卡和历史消息；根据实际环境报告 MySQL 测试是否运行，不将 mock 测试视为数据库一致性验证。
