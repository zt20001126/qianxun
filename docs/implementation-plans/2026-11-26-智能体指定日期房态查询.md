# 智能体指定日期房态查询实现方案

> 日期：2026-11-26  
> 状态：待审阅；本次仅制定方案，不修改业务代码。

## 目标与范围

管理员通过现有智能体对话，查询指定日期一间或全部房间的房态。正式订单覆盖该住宿夜时返回预订人姓名、入住及退房日期。日期未明确时向管理员追问；房间未指定时查询全部。仅返回完成任务所需字段，不提供手机号、金额等信息，不改变订单或房态。

以北京时间业务日期解释“今天、明天”等相对日期；工具接收明确的 `YYYY-MM-DD` 日期和可选房号。非法日期、参数类型错误或额外字段应拒绝；房号不存在时明确提示，不能当成空房。姓名为空时表示未记录。无日期范围限制，但须校验日期格式及有效性。

## 现有实现与口径

- `agent/core/tool/AgentTool.java` 和 `AgentToolRegistry.java` 自动收集工具并提供模型定义；`TodayBusinessDataTool.java` 是现有工具示例。`agent/core/node/ModelNode.java` 加载提示词，`AgentServiceImpl` 负责工具调用循环。
- `report/mapper/ReportMapper.java` 的 `findDashboardRooms` 与 `resources/mapper/report/ReportMapper.xml` 已一次查询指定日期的房间、非取消订单、预订人姓名、入住退房日期和封房，查询使用 `check_in <= date < check_out`。`DashboardRoomEntity` 已含订单原始状态。
- `report/service/impl/ReportServiceImpl.java` 的 `dashboard` 同时计算月度指标，不适合为了房态调用整套报表；其 `toDashboardRoom` 在连住后续夜晚返回 `OCCUPIED`，丢失了原始订单状态。应复用查询和房态转换，并在本次新增的内部结果中保留订单状态，不能将 `OCCUPIED` 直接解释成已入住。
- 后台月历约定不展示临时支付锁房。此次沿用该口径：空房仅表示无正式订单及管理员封房，不能保证当下可预订；需要预订时仍须经过库存校验。封房显示不可预订，不显示预订人。已取消订单不显示，退房当晚不占用；历史已完成订单按实际状态和原定日期显示，订单状态是查询时的当前状态，不推断历史当天实际入住状态。

## 接口与数据库影响

- `POST /api/admin/agent/chat`：保持现有请求、响应和管理员认证不变；通过既有对话完成查询。会话查询接口及 `GET /api/admin/room-calendar` 保持不变。新增的是内部模型工具定义，不新增 HTTP 接口或响应字段。
- 数据库结构无变更、无迁移或回填：读取 `room`（标识、房号、名称、楼层）、`orders`（房间、状态、预订人、入住退房及现有查询字段）、`room_block`（房间及封房日期）、`channels`（现有联查来源），均复用 `ReportMapper.xml` 和 `db/migration/V3__create_room_channel_creator_tables.sql`、`V4__create_availability_tables.sql` 中现有结构。工具结果只输出所需字段；不新增表、字段或索引。
- 该查询属于后台管理员能力，沿用现有 `/api/admin/agent/chat` 认证及权限边界；现有聊天过程可能将问题、回答保存为会话消息，预订人姓名因此可能随回答保留，应遵守当前会话访问和保存机制。

## 实施步骤和验收

1. **提取服务查询**：修改报表 Service 接口、实现及新增内部 VO。验收：指定日期返回各房间状态和订单摘要，`OCCUPIED` 的订单仍保留原始状态；不查询月度报表；原看板结构及结果不变。
2. **新增工具**：实现并注册工具，完成严格参数验证、过滤与序列化。验收：指定有效房号只返回该房，省略返回全部；未知房号明确提示；姓名缺失不编造；不返回手机号和财务信息。
3. **调整提示词**：让模型在日期明确时调用工具，日期不明确时追问。验收：说明查询日期、正确区分订单状态与住宿夜占用，不将空房承诺为可预订；对今日汇总和现有提问功能不造成冲突。
4. **自动化与回归**：工具单元测试覆盖合法、无效、权限边界对应现有聊天接口、重复查询；服务测试覆盖映射及不加载月报；MySQL 集成测试覆盖退房当日后续入住、跨月、连住、封房、取消及结果字段。执行后端相关测试和编译；如 MySQL/Docker 不可用，明确记录未验证范围。另用实际模型手工检查日期理解、工具选择和中文回答，不将单元测试等同真实模型验证。

## 假设和风险

- 沿用后台月历不展示临时锁房；回答中明确空房不保证可订。本方案不新增可订性查询。
- 查询过去或未来的日期时，订单状态是当前数据库状态；不声称其为历史时点状态，也不将未来订单当成已发生入住。
- 智能体生成内容存在不确定性，测试须分别验证工具事实输出和模型回答；执行阶段如发现现有查询无法满足上述语义，应先评估调整并更新方案。
