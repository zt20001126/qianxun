# 图片存储分阶段切换分析

> 日期：2026-11-27；状态：分析草案，尚未实施切换。实施前需确认历史地址处理方式、部署环境与验收窗口。

## 目标和现状

逐步将新图片和已复制图片的访问迁到腾讯云，同时保留阿里云回退能力。此前将 OSS 中当时的 85 张图片按原对象键复制到 COS，逐个下载并校验 SHA-256 一致；这是一次性快照，之后新增或变化的文件需要重新核对。两边桶级 ACL 当时均为公共读；未核实对象策略、CDN 和未来的权限变更。

- `backend/src/main/java/com/qianxun/homestay/modules/mall/service/impl/MallProductImageUploadServiceImpl.java` 使用阿里云 SDK 写入商城图片，返回公开地址；`POST /api/admin/mall/products/images` 被管理后台使用。
- `backend/src/main/java/com/qianxun/homestay/modules/storage/service/CosStorageService.java` 和实现提供 COS 上传、公开地址、签名地址能力；目前业务没有调用。
- `backend/src/main/java/com/qianxun/homestay/modules/room/service/impl/RoomImageUrlServiceImpl.java` 对 HTTP(S) 原样返回，对 `oss://` 生成阿里云签名；`RoomServiceImpl` 在小程序客房列表和详情调用它。后台房间数据直接返回已保存地址。
- `mall_product.images` 和 `room.images` 保存图片引用；商城商品图片、订单商品封面和后台房间管理都需要纳入检查。实时数据库中的实际引用、外部域名、签名地址及是否存在额外表尚未清点。
- `frontend/miniprogram/pages/around-guide/index.ts` 写有阿里云图片地址；Flyway V17/V18 也保存旧 URL，不能改写已执行迁移。
- COS 上传、签名地址和公开地址已通过一次真实测试；还未在真实微信小程序和 PC 后台验证迁移后图片展示。腾讯云文档提示新桶默认域名可能对浏览器预览有限制，不能仅以签名 GET 200 证明所有客户端都能内嵌显示。

## 推荐步骤

### 1. 清点、增量补齐与准备

1. 在实际目标环境只读导出 `room.images`、`mall_product.images` 的引用清单，逐项识别 OSS URL、`oss://`、第三方地址、COS URL 和无效值；检查商城订单封面的实际来源。以实际数据库为准，不将仓库搜索当成完整数据清点。
2. 对 OSS 和 COS 重新列目录、比对对象键、大小和内容哈希，增量补齐快照之后新增或改变的源文件；发现同名不同内容时停止并逐项处理，不覆盖目标。
3. 检查对象的实际匿名访问权限、Content-Type、缓存与必要元数据。不得将原本私有的对象转换为公开访问；`oss://` 对应对象的权限和用途需要逐项确认。
4. 在实际管理后台、微信开发者工具及真机验证 COS 图片展示。按实际使用的微信网络 API 核对合法域名、TLS、证书及防盗链，确认默认域名是否适用；如有需要再配置合法自定义域名。切换前保留旧域名。

验收：形成引用与文件对账清单；每个拟切换对象存在、内容一致且访问权限符合其用途；小程序房间、商城、攻略和后台图片展示正常。若不满足则不切换对应项。

### 2. 新上传切换，旧地址继续使用

拟在 `MallProductImageUploadServiceImpl` 中保留图片类型检查、对象键命名和原有 OSS 实现，增加明确的服务端供应商开关（默认 OSS），启用 COS 后调用 `CosStorageService`，接口路径、权限、请求和响应结构不变。环境变量在 `application.yml`、`docker-compose.yml` 和 `.env.example` 配置；非法值及选中 COS 却缺少配置时应明确报错，不静默降级或双写。可以将可复用部分按最小范围抽取，但不应绕过现有图片格式校验。

先在测试环境启用 COS，验证多种图片格式、非法文件、错误配置、云端故障、公开访问和后台保存；再按部署发布步骤启用。旧商品和房间 URL 依然指向 OSS，不需要同时迁移数据库。回退上传开关只影响未来上传；已经存入数据库的 COS URL 仍需 COS 持续可读，不能因回退就关闭 COS。

验收：新商品图片上传到 COS 并在后台和小程序正常显示，原有 OSS URL 仍可读；切回 OSS 后新上传再次进入 OSS，切换期间生成的 COS 图片仍正常显示。

### 3. 历史图片逐批迁移

推荐在清单核对后，以受控、可审计的增量方式更新 `room.images` 与 `mall_product.images` 中**已确认成功复制且可访问**的引用：保留图片顺序、其他域名、查询参数和不匹配项；只匹配确切的原桶和对象键，禁止全库字符串替换。使用备份记录每条原值、新值和主键；事务中按旧值比较后更新，避免覆盖管理员期间的修改。运行前先预览、统计，迁移后逐项复核；通过新增版本化迁移或单独受控工具实施，具体方式需按实际部署与数据量确认，不修改 V17/V18。

不要把 `oss://` 引用当作普通公开 URL 直接替换：先确认对象是否确为公开、历史隐私要求及 COS 目标权限。若仍需私有读取，应设计并明确 COS 引用格式与签名解析、对后台与小程序的影响后再处理，保留原 OSS 解析能力。

切换 `frontend/miniprogram/pages/around-guide/index.ts` 中的攻略图需发布小程序版本，旧版本仍依赖阿里云；PC 后台也应验证房间编辑和图片预览。根据真实客户端表现决定是否需要自定义 COS 域名。

回滚时，仅对仍等于本次新值的记录恢复备份旧值，先处理迁移后被管理员编辑的冲突；小程序版本回退也不能保证所有用户立即更新。切换前后都应保留两边文件。

### 4. 观察与最终收尾

观察周期和停用时间需由用户确认。清点生产数据库、配置、日志、代码、外部调用和旧版客户端是否仍依赖 OSS；确认 COS 新旧图片、备份和恢复方案后，再单独决定是否停用阿里云。未完成清点和确认前保留 OSS 数据、读取凭据与旧域名。

预期自动化检查：OSS/COS 两种路径与故障、配置空缺、类型校验、旧地址解析、地址匹配与迁移冲突、图片顺序和回滚；执行后端 Maven 测试、管理后台构建和小程序类型检查。真实环境检查：抽样 COS 的房间、商品和攻略图片，逐项核对存量迁移、PC 后台、微信开发者工具与真机。上述测试尚未执行，不承诺客户端零中断。

## 待实施前确认

- 历史 `oss://` 是否需要保持私有，以及哪些对象属于该类；运行环境和数据库引用以清点结果为准。
- 历史地址采用数据库逐批更新，还是先维持旧地址更长时间；本文推荐逐批更新，但不把它当作已经批准的数据变更。
- 小程序实际使用的域名和上架版本、发布窗口及观察时长；如默认 COS 域名不适用需确定自定义域名。
- 上述均不授权实施、切换、修改数据库或停用 OSS。本阶段仅为分析。
