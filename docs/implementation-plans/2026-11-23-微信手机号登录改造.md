# 微信手机号登录改造方案

> 后续用户确认保留微信授权登录，并同时恢复直接输入手机号登录。本文前半部分记录微信授权登录改造的历史方案；新增 A05 手机号登录契约见 `docs/03-接口契约/芊浔民宿_接口扩展_微信手机号登录_20261123.md`。

## 已确认需求

- 小程序只通过微信手机号授权登录。服务端获取微信手机号与本小程序 OpenID，以手机号匹配会员；已有同手机号且 OpenID 为空的会员绑定原账号，保留会员 ID、订单和积分。
- 同一手机号已绑定其他 OpenID，或同一 OpenID 已绑定其他会员时，拒绝登录并提示“账号绑定信息存在冲突，请联系管理员处理”；不自动换绑、合并或修改数据。
- 新会员创建时保存手机号和 OpenID；已绑定同一身份重复登录正常签发会员 JWT。管理员登录与管理员预建会员能力不改变。
- 当前范围为登录改造；支付继续沿用现有二次身份校验，不增加换绑界面或后台处理功能。

## 当前实现与目标流程

`AppAuthController.login` 接收 `PhoneLoginRequest.phone`，`AuthServiceImpl.loginByPhone` 使用 `MemberMapper.xml` 的 `upsertLoginProfile` 创建或查询会员并签发 JWT。前端登录页输入手机号，`services/auth.ts` 直接提交。该入口无法验证手机号归属。

`WechatIdentityServiceImpl` 已能向微信换取 OpenID 和手机号，但其 `verifyAndBindOpenId` 依赖已有会员 ID，且受 `app.payment.wechat.enabled` 控制；支付模块也调用它。`members` 已有 phone 和可空 openid 唯一索引。`JwtAuthenticationFilter` 当前仅解析 JWT，不检查签发时代，旧令牌仍可使用。

目标流程：用户主动点击微信手机号授权 → 前端取得手机号授权 code 和 `wx.login` code → 后端向微信换取手机号、OpenID → 事务内按手机号查找或创建并核对 OpenID 归属 → 成功后签发 JWT。微信网络调用放在数据库事务外；授权拒绝、微信错误、凭证无效或身份冲突均不签发令牌。

## 接口与数据库影响

| 接口 | 操作 | 影响 |
| --- | --- | --- |
| `POST /api/app/auth/login` | 修改 | 请求由 `{phone}` 改为 `{login_code, phone_code}`；响应保持 JWT、有效期和会员资料。旧请求失败，旧小程序不再兼容。绑定冲突返回 409 和联系管理员提示。 |
| `GET /api/app/auth/me` | 不变 | 继续依据会员 JWT 查询。 |
| 现有住宿与商城微信预支付接口 | 不变 | 保持其当前 code 请求和身份验证；回归验证重构不改变支付行为。 |

数据库 `members.phone`、`members.openid` 和各自唯一索引保持不变；`openid` 继续可空以支持管理员预建会员。现有空值不批量填充，首次成功授权时绑定；不新增表或字段。已应用迁移不修改；实际数据库索引与字段需上线前核对。唯一键冲突或并发插入需在合适事务边界重新查询并辨别同身份重试和真实冲突，禁止误将其他会员当作登录结果。

## 实施步骤与验收

1. 更新需求及接口文档，明确冲突处理和旧版不兼容。验收：文档与授权流程、字段及错误行为一致。
2. 分离微信身份兑换与支付开关，保留支付调用路径。验收：模拟支付配置下也能兑换身份；微信失败不创建会员、不签令牌，支付校验行为保留。
3. 实现事务内查找、创建及绑定。验收：已有未绑定会员 ID、积分、订单不变；新会员只创建一次；重复同身份登录成功；两类身份冲突均返回 409 且数据不变。真实 MySQL 验证并发争用。
4. 修改登录接口和小程序页面。验收：页面没有手输手机号入口；拒绝授权或请求失败可重试；直接提交旧 `phone` 请求不能登录；成功保存 JWT 并正常跳转。
5. 修改会员令牌版本检查。验收：改造前会员 JWT 访问受保护接口返回 401，新会员 JWT 正常，管理员 JWT 不受影响。
6. 执行相关后端单元、集成及 MySQL 并发测试，小程序类型检查与构建；核对真实微信环境中的授权、凭证有效期和主体权限。上述为计划，尚未执行。

## 上线与风险

- 上线前确认微信小程序主体已开通手机号获取能力，配置 AppID 和服务端 AppSecret，检查接口调用条件和平台费用；微信凭证、手机号、OpenID、会话密钥和 access token 不写入日志。
- 前后端需要协调发布：旧客户端无法使用新接口，旧会员登录态会被清除并需要重新授权。保留旧客户端将造成无法登录，不提供不安全的手机号兼容入口。
- 旧代码回滚可能重新开放手机号直接登录，必须结合访问控制和部署方案处理；不要把恢复不安全入口当作无风险回滚。
- 手机号由运营商重新分配时，尚未绑定 OpenID 的历史账号仍可能被新的手机号持有人关联；本需求按手机号关联旧账号，需由业务接受并在上线前评估历史数据。
