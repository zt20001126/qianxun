# 芊浔民宿数据库表设计文档

> 版本：V1.1（2026-11-17）  
> 依据：《芊浔民宿需求规格说明书 V1.5》及后续确认的订单编号、统一金额、主播额外提成规则。  
> 范围：第一期逻辑表结构设计；**不是可直接执行的建表 SQL**。未最终确认的业务规则单独标注。

## 1. 统一设计规范

- 数据库：MySQL 8.0，InnoDB，`utf8mb4`；表名使用小写 `snake_case`，业务表使用单数或复数保持下表约定，不混用同义字段。
- 主键：`id BIGINT UNSIGNED`；关联键统一 `<对象>_id BIGINT UNSIGNED`；主键与外键索引按实际关系建立。
- 金额：`DECIMAL(12,2)`，人民币元，默认非负；积分：`INT`，流水变动值允许负数。
- 日期：`DATE`；时间：`DATETIME(3)`，服务端统一时间基准，业务截止时间按北京时间判断；`created_at`、`updated_at` 由系统维护。
- 状态/渠道使用稳定的英文编码，展示时映射中文；布尔字段使用 `TINYINT(1)`，例如 `enabled`。
- **必填**指持久化时必须存在，不代表管理员必须手工输入；**可空**指业务允许缺省；**计算**表示原则上不冗余持久化。
- 手机号使用 `VARCHAR(20)`，不使用数字类型；敏感信息须限制访问并按需要脱敏。
- 所有金额更新与积分、支付、订单状态更新应使用事务；关键外部回调和积分奖励必须有幂等约束。

## 2. 表清单（13 张正式表 + 1 张可选表）

| 序号 | 表名 | 业务职责 | 备注 |
|---:|---|---|---|

| 7 | `order_amount` | 订单金额及提成 | 与订单一对一 |
| 8 | `booking_lock` | 支付前临时预订与锁房 | 支持超时释放 |
| 9 | `payments` | 微信支付交易 | 只记录实际微信支付 |

## 3. 字段明细

### 3.1 `room` — 房间表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 房间ID |
| `number` | VARCHAR(10) | NOT NULL, UNIQUE | 房号：101、102、103、201、202、203 |
| `name` | VARCHAR(80) | NOT NULL | 房型名称 |
| `floor` | SMALLINT | NOT NULL | 楼层 |
| `price` | DECIMAL(12,2) | NOT NULL | 每晚基础房价 |
| `capacity` | SMALLINT UNSIGNED | NOT NULL | 最大入住人数 |
| `bed_info` | VARCHAR(120) | NULL | 床型及数量 |
| `area` | DECIMAL(6,2) | NULL | 面积，平方米 |
| `facilities` | JSON | NULL | 设施列表 |
| `images` | JSON | NULL | 图片 URL 字符串数组，按数组顺序展示 |
| `description` | TEXT | NULL | 房间介绍 |
| `enabled` | TINYINT(1) | NOT NULL DEFAULT 1 | 是否上架展示；不替代封房 |
| `created_at` | DATETIME(3) | NOT NULL | 创建时间 |
| `updated_at` | DATETIME(3) | NOT NULL | 更新时间 |

### 3.2 `room_block` — 封房表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 封房ID |
| `room_id` | BIGINT UNSIGNED | FK, NOT NULL | 房间ID |
| `start_date` | DATE | NOT NULL | 首个不可订住宿夜晚 |
| `end_date` | DATE | NOT NULL | 结束日期，不包含当天 |
| `reason` | VARCHAR(200) | NULL | 原因 |
| `created_at` | DATETIME(3) | NOT NULL | 创建时间 |

约束：`end_date > start_date`；封房不得与有效订单或锁房冲突。取消封房可直接删除或后续增加停用状态，第一期建议删除。

### 3.3 `channels` — 渠道表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 渠道ID |
| `name` | VARCHAR(30) | NOT NULL | 渠道名称 |
| `enabled` | TINYINT(1) | NOT NULL DEFAULT 1 | 是否启用 |
| `created_at` | DATETIME(3) | NOT NULL | 创建时间 |
| `updated_at` | DATETIME(3) | NOT NULL | 更新时间 |

初始渠道：小程序、抖音、美团、携程、同程、飞猪、途家。以 `channels.id` 作为订单关联键；系统识别小程序渠道时使用初始化配置中固定的渠道 ID，不依赖渠道名称字符串匹配。

### 3.4 `creators` — 主播/达人表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 主播ID |
| `name` | VARCHAR(80) | NOT NULL | 主播名称 |
| `channel_id` | BIGINT UNSIGNED | FK, NOT NULL | 所属渠道 |
| `enabled` | TINYINT(1) | NOT NULL DEFAULT 1 | 是否启用 |
| `created_at` | DATETIME(3) | NOT NULL | 创建时间 |
| `updated_at` | DATETIME(3) | NOT NULL | 更新时间 |

建议索引：`(channel_id, name)`；不强制主播名称全局唯一。订单仅关联一个主播，第一期不做多人分成。

### 3.5 `members` — 会员及小程序用户表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 内部会员ID，不在页面展示 |
| `phone` | VARCHAR(20) | NOT NULL, UNIQUE | 已验证或后台录入的会员手机号 |
| `openid` | VARCHAR(100) | NULL, UNIQUE | 小程序微信身份；后台预建会员可空 |
| `nickname` | VARCHAR(80) | NULL | 昵称 |
| `avatar` | VARCHAR(500) | NULL | 头像地址 |
| `growth_points` | INT UNSIGNED | NOT NULL DEFAULT 0 | 累计成长积分 |
| `points` | INT UNSIGNED | NOT NULL DEFAULT 0 | 当前可用积分 |
| `created_at` | DATETIME(3) | NOT NULL | 创建时间 |
| `updated_at` | DATETIME(3) | NOT NULL | 更新时间 |

- `phone` 是业务去重键；`id` 是稳定内部关联键。**预订手机号不一定是下单会员手机号**，不能直接用 `orders.phone` 代替 `member_id`。
- 首次登录通过微信提供的手机号验证流程匹配已有会员，再绑定 `openid`；不得仅凭输入手机号认领会员。
- 会员等级不存储，根据 `growth_points` 计算：普通 0–499、银卡 500–999、金卡 1000–1499、钻石 ≥1500。
- 实际部署时须处理手机号变更、OpenID 绑定冲突及并发首次登录。

### 3.6 `orders` — 正式订单表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 订单ID |
| `order_no` | VARCHAR(20) | NOT NULL, UNIQUE | 本系统订单编号 |
| `platform_order_no` | VARCHAR(100) | NULL | 外部平台订单号 |
| `room_id` | BIGINT UNSIGNED | FK, NOT NULL | 房间ID |
| `channel_id` | BIGINT UNSIGNED | FK, NOT NULL | 订单来源ID |
| `creator_id` | BIGINT UNSIGNED | FK, NULL | 主播ID；未选择主播为空 |
| `member_id` | BIGINT UNSIGNED | FK, NULL | 下单/奖励归属会员；外部订单可空 |
| `guest_name` | VARCHAR(80) | NULL | 预订人；小程序必填 |
| `phone` | VARCHAR(20) | NULL | 预订联系电话；小程序必填 |
| `guest_count` | SMALLINT UNSIGNED | NULL | 入住人数；小程序必填 |
| `check_in` | DATE | NOT NULL | 入住日期 |
| `check_out` | DATE | NOT NULL | 退房日期（不含当晚） |
| `status` | VARCHAR(20) | NOT NULL | 订单状态 |
| `remark` | VARCHAR(500) | NULL | 备注 |
| `created_at` | DATETIME(3) | NOT NULL | 创建时间 |
| `updated_at` | DATETIME(3) | NOT NULL | 更新时间 |

- `order_no` 格式：`QXYYYYMMDDNNNN`，例如 `QX202611170001`。`NNNN` 为**当天按事务安全分配的流水号**，不是手机号后四位；若日订单量超出四位则扩展流水位数，不得重号。
- `order_no` 是小程序订单列表和详情展示的订单号，`id` 仅供内部关联。外部订单也生成本系统订单号，平台原订单号另存。
- `status`：`PENDING_CONFIRM` 待确认、`PENDING_CHECKIN` 待入住、`CHECKED_IN` 已入住、`COMPLETED` 已完成、`CANCELLED` 已取消。
- 小程序订单支付成功才生成正式订单；第三方订单允许直接录入历史已完成订单。
- **无主播时 `creator_id = NULL`**；对应金额表的两项主播提成均为 `0.00`。
- 唯一索引建议：`(channel_id, platform_order_no)`（MySQL 允许多个 NULL）；另建 `(room_id, check_in, check_out)`、`(member_id, status)`、`(channel_id, status)` 查询索引。
- 房态冲突必须在事务中对整个 `[check_in, check_out)` 区间校验，普通唯一索引不能代替日期重叠检查。

### 3.7 `order_amount` — 订单金额表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 金额记录ID |
| `order_id` | BIGINT UNSIGNED | FK, NOT NULL, UNIQUE | 一笔订单仅一条金额记录 |
| `paid_amount` | DECIMAL(12,2) | NOT NULL | 顾客实付金额（小程序为积分抵扣后的微信实付） |
| `platform_fee` | DECIMAL(12,2) | NOT NULL DEFAULT 0 | 平台手续费 |
| `platform_commission` | DECIMAL(12,2) | NOT NULL DEFAULT 0 | 平台达人提成 |
| `extra_commission` | DECIMAL(12,2) | NOT NULL DEFAULT 0 | 达人额外提成，由后端按规则维护 |
| `expected_amount` | DECIMAL(12,2) | NULL | 预期收入；有主播时填写，无主播为空 |
| `net_amount` | DECIMAL(12,2) | GENERATED ALWAYS AS (`paid_amount` - `platform_fee` - `platform_commission` - `extra_commission`) STORED | 商家到手金额；数据库自动计算，不手工填写 |
| `created_at` | DATETIME(3) | NOT NULL | 创建时间 |
| `updated_at` | DATETIME(3) | NOT NULL | 更新时间 |

**字段显示顺序已按要求固定**：顾客实付金额 → 平台手续费 → 平台达人提成 → 达人额外提成 → 预期收入 → 商家到手金额。**不设置小程序积分抵扣金额字段**，其历史人民币抵扣金额由 `points_log.discount_amount` 记录。

**计算及校验**：

1. 未选择主播：`orders.creator_id = NULL`，`platform_commission = 0.00`、`extra_commission = 0.00`、`expected_amount = NULL`；平台手续费可正常录入。
2. 已选择主播：填写 `expected_amount`，后端计算 `extra_commission = GREATEST(0, paid_amount - platform_fee - platform_commission - expected_amount)`；计算结果小于零时按零处理。
3. `net_amount = paid_amount - platform_fee - platform_commission - extra_commission`。此字段由数据库生成，查询时可直接使用，避免人工维护造成不一致。
4. 修改实付金额、平台手续费、平台达人提成或预期收入时，必须在同一事务内重新计算并保存额外提成；已经发放的积分不重算、不追回。
5. 小程序正常订单默认平台手续费和两项主播提成均为零；微信支付手续费第一期不计入平台手续费。
6. 各金额非负；不允许系统将负额外提成保存为负数。若计算后商家到手金额为负，应提示管理员核查。

**例**：实付 ¥300，平台手续费 ¥15，平台达人提成 ¥20，预期收入 ¥200，额外提成 ¥65，商家到手 ¥200。

### 3.8 `booking_lock` — 临时预订/锁房表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 临时预订ID |
| `member_id` | BIGINT UNSIGNED | FK, NOT NULL | 下单会员 |
| `room_id` | BIGINT UNSIGNED | FK, NOT NULL | 房间ID |
| `check_in` | DATE | NOT NULL | 入住日期 |
| `check_out` | DATE | NOT NULL | 退房日期 |
| `guest_name` | VARCHAR(80) | NOT NULL | 预订人快照 |
| `phone` | VARCHAR(20) | NOT NULL | 联系电话快照 |
| `guest_count` | SMALLINT UNSIGNED | NOT NULL | 入住人数 |
| `remark` | VARCHAR(500) | NULL | 备注 |
| `room_amount` | DECIMAL(12,2) | NOT NULL | 支付前房费原价快照 |
| `discount_amount` | DECIMAL(12,2) | NOT NULL DEFAULT 0 | 积分抵扣金额快照 |
| `points_used` | INT UNSIGNED | NOT NULL DEFAULT 0 | 预占积分数量 |
| `amount` | DECIMAL(12,2) | NOT NULL | 待支付金额 |
| `status` | VARCHAR(20) | NOT NULL | `PENDING`/`PAID`/`EXPIRED`/`CANCELLED` |
| `expires_at` | DATETIME(3) | NOT NULL | 锁房失效时间 |

说明：有效锁房占用住宿区间；超时释放。积分应以可核对的预占机制处理，防止重复支付时超额抵扣。锁房过期与微信支付成功回调竞争时须事务化处理，不得重复创建订单或超售。

### 3.9 `payments` — 微信支付表

| `payment_no` | VARCHAR(64) | NOT NULL, UNIQUE | 商户支付单号 |

| `amount` | DECIMAL(12,2) | NOT NULL | 微信支付金额 |

说明：支付成功由服务端核验后生成正式订单；回调幂等。第三方平台订单不生成虚假的微信支付记录。

### 3.10 `refunds` — 退款表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 退款ID |
| `order_id` | BIGINT UNSIGNED | FK, NOT NULL | 订单ID |
| `payment_id` | BIGINT UNSIGNED | FK, NOT NULL | 原支付ID |
| `refund_no` | VARCHAR(64) | NOT NULL, UNIQUE | 商户退款单号 |
| `wechat_refund_id` | VARCHAR(64) | NULL, UNIQUE | 微信退款单号 |
| `amount` | DECIMAL(12,2) | NOT NULL | 退款金额 |
| `status` | VARCHAR(20) | NOT NULL | `PENDING`/`SUCCESS`/`FAILED` |
| `reason` | VARCHAR(300) | NULL | 退款原因/失败说明 |
| `refunded_at` | DATETIME(3) | NULL | 完成时间 |

自助取消规则：仅待确认、待入住且严格早于入住当天北京时间18:00；已完成订单不允许普通取消或退款。退款与积分返还必须分别幂等，异常可重试。

### 3.11 `points_log` — 积分流水表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 流水ID |
| `member_id` | BIGINT UNSIGNED | FK, NOT NULL | 会员ID |
| `order_id` | BIGINT UNSIGNED | FK, NULL | 关联订单 |
| `type` | VARCHAR(30) | NOT NULL | 积分业务类型 |
| `points` | INT | NOT NULL | 可用积分变动，正/负 |
| `growth_points` | INT | NOT NULL DEFAULT 0 | 成长积分变动 |
| `amount` | DECIMAL(12,2) | NULL | 自动奖励时的实付金额快照 |
| `discount_amount` | DECIMAL(12,2) | NULL | 积分抵扣时的人民币金额快照；用于还原下单原价 |
| `ref_no` | VARCHAR(100) | NULL, UNIQUE | 业务幂等编号 |
| `remark` | VARCHAR(300) | NULL | 备注 |
| `created_at` | DATETIME(3) | NOT NULL | 创建时间 |

`type` 建议：`ORDER_REWARD` 订单奖励、`HISTORY_REWARD` 历史消费补发、`GIFT` 赠送补偿、`REDEEM` 积分抵扣、`RETURN` 取消返还、`ADJUST` 异常调整。人工发放可在备注中注明操作人；若未来需要严谨追踪管理员身份，可增加 `admin_id`，不必引入通用操作日志表。

- 历史消费补发：`points > 0` 且 `growth_points > 0`；赠送补偿：仅 `points > 0`，`growth_points = 0`。
- 订单完成后自动奖励：`FLOOR(paid_amount)`；小程序奖励归属下单会员，外部订单有有效预订手机号才自动创建/关联会员并发放。
- 同一订单 `ORDER_REWARD` 必须仅成功一次；推荐 `ref_no = ORDER_REWARD:<order_id>` 并唯一约束。
- 自动奖励发放后订单金额修改不追回、不重算、不补发。
- 积分抵扣汇率：普通30、银卡25、金卡20、钻石15积分/元，单笔最多抵扣房费20%。抵扣与返还流水须关联同一业务，不能重复扣减或返还。

### 3.12 `expenses` — 经营支出表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 支出ID |
| `content` | VARCHAR(300) | NOT NULL | 支出内容 |
| `amount` | DECIMAL(12,2) | NOT NULL | 支出金额 |
| `date` | DATE | NOT NULL | 实际支出归属日期 |
| `created_at` | DATETIME(3) | NOT NULL | 创建时间 |
| `updated_at` | DATETIME(3) | NOT NULL | 更新时间 |

`date` 与 `created_at` 不同：补录历史水电费时按实际支出日期统计。经营利润 = 净营业额 − 经营支出。

### 3.13 `admin` — 后台管理员表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 管理员ID |
| `username` | VARCHAR(60) | NOT NULL, UNIQUE | 登录账号 |
| `password_hash` | VARCHAR(255) | NOT NULL | 安全哈希，不存明文 |
| `enabled` | TINYINT(1) | NOT NULL DEFAULT 1 | 是否启用 |
| `created_at` | DATETIME(3) | NOT NULL | 创建时间 |
| `updated_at` | DATETIME(3) | NOT NULL | 更新时间 |

第一期仅一个管理员账号，不设计角色权限表；即使系统设置页不显示账号管理，也需有安全登录机制。若管理员认证完全由现有外部身份系统承担，可不创建此表。

### 3.14 `order_guest` — 实际入住人表（可选）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 入住人记录ID |
| `order_id` | BIGINT UNSIGNED | FK, NOT NULL | 关联订单 |
| `name` | VARCHAR(80) | NOT NULL | 实际入住人姓名 |
| `age` | SMALLINT UNSIGNED | NULL | 年龄（如确需记录） |
| `created_at` | DATETIME(3) | NOT NULL | 创建时间 |

只有确定要在系统登记实际入住人时启用；不等于预订人，且不在小程序预订表单强制填写身份证号。涉及住宿实名登记等法定义务，应按当地要求另行确认数据范围和保护措施。

## 4. 关系与计算规则

### 4.1 主要关联

- `room` 1:N `room_block`、`orders`、`booking_lock`；房间图片列表直接保存在 `room.images`。
- `channels` 1:N `creators`、`orders`；`creators` 1:N `orders`（订单可无主播）。
- `members` 1:N `orders`、`points_log`、`booking_lock`；订单会员关联可空。
- `orders` 1:1 `order_amount`；`orders` 1:N `refunds`、`order_guest`（可选）。
- `booking_lock` 1:N `payments`（支持失败后重试发起支付）；`payments` 在成功后关联 `orders`。

### 4.2 房态日历

无需每日房态表。依据订单、封房、有效锁房计算六种正式房态：空房、已预订、待入住、已入住、已退房、不可预订。连住后续夜晚仅展示「占用」，不是独立状态；退房当天不占房。冲突判断使用整个 `[check_in, check_out)` 区间。

### 4.3 经营统计

- 不创建 `order_night`；跨月订单在报表查询时按**住宿间夜数平均分摊**实付金额和三类费用，尾差精确到分。
- 净营业额 = 实付金额 − 平台手续费 − 平台达人提成 − 达人额外提成。
- 经营利润 = 净营业额 − 经营支出。
- 已核、待核为报表统计分类，按订单状态与住宿夜晚归属计算，不作为金额表重复字段。
- 订单完成后不可普通取消或退款；修改外部订单金额后报表重算，但已发积分保持原值。
- 第一阶段微信支付手续费不计入经营成本或平台手续费。

## 5. 必要索引、约束与一致性

1. `orders.order_no`、`payments.payment_no`、`refunds.refund_no` 唯一；`order_amount.order_id` 唯一。
2. `members.phone` 唯一，`members.openid` 唯一且允许为空；`channels.name` 建议唯一，渠道识别使用初始化的固定 ID。
3. `orders(channel_id, platform_order_no)` 在平台订单号非空时防重；无平台订单号的导入仅能疑似匹配并由管理员确认，不能保证自动去重。
4. 积分自动奖励采用稳定唯一业务幂等号；支付成功、退款成功及积分返还分别幂等。
5. 同一房间住宿日期区间的有效订单、有效封房、有效临时锁房不得重叠；在事务/锁机制中执行，不只依靠普通索引。
6. 不允许出现负房价、负费用、负可用积分；金额修改后报表按最新金额动态分摊计算。
7. 订单编号日流水分配需并发安全；可使用数据库计数器或锁机制，不能依赖 `SELECT MAX(order_no)+1` 无锁拼接。
8. 历史订单不因房间现价、会员等级、积分兑换比例变化而修改已确认的成交快照。

## 6. 不创建的表及原因

| 暂不创建 | 原因 |
|---|---|
| 每日房态表 | 根据订单、封房和锁房动态计算 |
| 会员等级表 | 四档固定门槛，可由成长积分计算 |
| 净营业额汇总表 | 从订单金额实时计算 |
| 月度经营报表表 | 从订单、间夜和支出汇总 |
| 单独 `users` 表 | 第一阶段小程序用户与会员合并为 `members` |
| 通用操作日志表 | 用户明确第一期不需要；支付/退款/积分业务流水仍保留 |
| 数据导出、备份任务表 | 第一阶段不开发数据导出与备份功能 |
| 独立小程序订单金额表 | 七种渠道共用 `order_amount` |
| `room_image` | 房间图片列表存入 `room.images` JSON |
| `order_night` | 第一阶段在报表查询时计算间夜分摊 |

## 7. 待确认或实施时需明确的细节

1. **封房表最终方案**：目前推荐保留 `room_block` 以支持指定日期封房；如果最终决定只支持整间房上下架，可取消此表并使用 `room.enabled`，但无法表达单独封锁某几晚。
2. **预期收入录入方式**：当前设计为**有主播订单逐单填写 `expected_amount`**，无主播为空；是否以后按房间/主播自动带入尚未确认。
3. **第三方平台补贴**：顾客实付与平台实际结算差额如何入账尚未确认；第一期以录入实付为统计依据。
4. **重复导入**：没有平台订单号时的疑似重复识别与人工确认流程待细化。
5. **积分批量导入**：建议区分历史消费积分与赠送补偿积分；导入模板字段待确认。
6. **订单状态和金额修改权限**：外部订单允许修改金额并重算；小程序已付款订单不开放顾客改价。管理员是否允许更正小程序金额需另行确认，不能修改微信真实交易金额。
7. **支付异常**：支付成功但锁房已过期或房间已被占用时，必须制定异常订单与退款补偿流程，不能直接强行生成冲突订单。
8. **实际入住人**：是否启用 `order_guest` 及登记字段范围，按实际运营与当地规定确认。
9. **报表已核/待核口径**：沿用需求文档的内部统计概念，需在接口设计时统一状态归属规则，避免与实际到账混淆。
