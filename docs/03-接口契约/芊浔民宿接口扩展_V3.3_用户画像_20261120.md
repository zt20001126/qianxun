# 芊浔民宿接口扩展 V3.3：顾客画像

> 管理端接口需要管理员认证；JSON 使用 `snake_case`，统一返回 `ApiResponse`。

## 1. 用户画像列表

`GET /api/admin/portraits?page=1&size=20&guest_name=&phone=`

按姓名、手机号分页筛选。手机号是画像唯一标识；姓名仅展示。画像返回字段包括：

- `id`、`guest_name`、`phone`、`age`、`party_type`、`inferred_region`、`tags[]`、`admin_remark`
- `member`：画像手机号是否匹配会员表
- `completed_order_count`、`cumulative_paid_amount`：仅统计已完成订单
- `completed_orders[]`：订单号、入住日期、实付金额和该订单两类备注
- `orders[]`：该手机号所有关联订单及逐单备注，供持续编辑

`orders[].remark` 是顾客每次下单的备注。画像页把这些备注聚合在同一栏展示，保存时仍逐笔更新原订单备注。

## 2. 修改画像

`PUT /api/admin/portraits/{id}`

请求包含 `age`、`party_type`、`inferred_region`、`tags[]`、`admin_remark` 和 `order_remarks[]`。`order_remarks[]` 每项包含 `order_id`、`remark`、`admin_remark`，且订单必须属于当前画像。画像资料与备注在一个事务中保存；订单状态、金额、积分、日期及库存不变。订单状态不限制编辑。请求不接受身份证号。

## 3. 标签选项

- `GET /api/admin/portrait-tags`：读取系统预置及管理员新增的可选标签，返回 `[{id, name}]`。
- `POST /api/admin/portrait-tags`：新增全局可复用标签，请求 `{ "name": "自定义标签" }`；同名重复提交复用已有标签。
- 画像请求中的 `tags[]` 保存已选择的标签名称；只接受当前可选列表内的标签。

## 4. 订单接口扩展

- `POST /api/admin/orders` 可选接收 `booker_portrait`，用于第三方订单创建时填写画像。
- `POST /api/admin/orders/{id}/check-in` 可选接收 `booker_portrait`，随办理入住保存。
- `PUT /api/admin/orders/{id}` 可选接收订单级 `admin_remark`。
- 第三方订单创建请求可选接收订单级 `admin_remark`。
- 管理端订单详情增加 `admin_remark` 与 `booker_portrait`；画像详情包含年龄、群体、地区和标签。

画像级 `admin_remark` 与订单级 `admin_remark` 是不同字段，分别表示手机号顾客的长期管理记录和单笔订单内部备注。
