# 芊浔民宿接口设计文档

> 版本：V3.1｜日期：2026-11-18  
> 依据：《芊浔民宿需求规格说明书 V3.1》《芊浔民宿数据库表设计文档 V3.1》  
> 适用：微信小程序、PC 管理后台、Spring Boot 后端。本文为**拟定接口契约**，不是已有接口清单。

## 1. 统一规范

- 前缀：`/api`；小程序用户接口 `/api/app`，后台接口 `/api/admin`；第一期不提供微信支付回调。
- HTTP：`GET` 查询、`POST` 创建/动作、`PUT` 更新、`DELETE` 删除。请求/响应使用 JSON，文件上传除外。
- 命名：JSON 使用 `snake_case`，与数据库字段一致；路径使用小写复数名，动作使用短语义路径。
- 认证：小程序微信手机号授权登录和后台管理员登录均签发 **30 天有效期 JWT**（第一期均无刷新接口）；会员登录微信认证细则见《微信手机号登录接口扩展》。第一期不调用微信支付接口。
- 日期：`YYYY-MM-DD`；月份：`YYYY-MM`；时间：ISO 8601（明确时区）。金额：人民币元，JSON 中建议用**字符串**表示（如 `"200.00"`），避免浮点误差。
- 分页：`page` 从 1 开始，`size` 默认 20；分页响应 `list`、`total`、`page`、`size`。
- 返回：`{"code":200,"message":"success","data":{...}}`。失败时 `code` 为业务错误码，`message` 为可读提示；HTTP 状态码与错误类别一致。
- 主要错误：`400` 参数错误、`401` 未登录、`403` 无权限、`404` 不存在、`409` 日期冲突/状态冲突、`422` 业务规则不满足、`500` 服务端异常。第一期无微信回调。
- 写接口必须校验权限、字段和状态；支付、退款、积分等操作须幂等；前端显示的房态和价格不能代替提交时的后端复核。
- 标记：**必**=必填；**选**=可选；**系统**=后端自动生成。除特别注明，所有 `id` 为数据库主键，不等于房间号（如 `101`）。

### 1.1 订单状态与费用

- 订单状态：`PENDING_CONFIRM` 待确认、`PENDING_CHECKIN` 待入住、`CHECKED_IN` 已入住、`COMPLETED` 已完成、`CANCELLED` 已取消。
- 订单号：`QXYYYYMMDDNNNN`，后端并发安全生成；订单与金额一对一。
- 无主播：`creator_id=null`，`platform_commission=0.00`、`extra_commission=0.00`、`expected_amount=null`。
- 有主播：`extra_commission=max(0, paid_amount-platform_fee-platform_commission-expected_amount)`，预期收入必填。
- `net_amount=paid_amount-platform_fee-platform_commission-extra_commission`，由数据库生成列计算，不允许客户端传入。
- 小程序 `paid_amount` 为积分抵扣后的模拟实付；积分抵扣人民币快照保存在 `points_log.discount_amount`，**不在** `order_amount` 增加积分抵扣字段。

### 1.2 日期占用与报表

- 住宿日期区间为 `[check_in, check_out)`：含入住日、不含退房日。
- 有效订单（除 `CANCELLED`）、管理员封房 `room_block`、未过期有效锁房 `booking_lock` 均可占用日期；历史已完成订单仍保留历史占用记录。
- 不创建每日房态表、`room_image`、`order_night`；图片使用腾讯云 COS，URL 存 `room.images` JSON；跨月间夜金额在查询时按晚平均分摊并处理分币尾差。
- 小程序预订日历按月查询，默认打开当月；仅允许选择北京时间从今天起连续 **60 个自然日**内的入住和退房日期（今天为第 1 天），后端强制校验。小程序只显示可预订/不可预订，不暴露后台详细房态。
- 房间退房日期不占用间夜；允许当天退房、当天入住；超期未办理退房不延长原订单占用。
- 房间价格仅单一基础价格；修改价格仅影响新创建订单，已有有效待支付交易保留原价。

### 1.3 第一阶段补充约定

- 不开发批量导入与用户画像；O11、M07 为删除的历史编号，不得生成接口。
- 积分使用量只能为非负整数；抵扣金额采用精确十进制计算 `floor(points_used / rate * 100) / 100`，向下取整到分，并校验不超过房费 20%。
- 后台月历不显示待支付锁房，后台录单和封房写操作仍须校验有效锁房。
- 旧库 `homestay_db.room`、`room_type` 的数据迁移是一次性运维脚本，不属于公开业务接口。
- COS 图片文件上传与 URL 保存须分离；当前接口清单不包含 COS 上传接口，实施时可采用后台直传 COS 的安全临时凭证方案，不能在客户端写入永久密钥。

## 3. 模块一：认证管理

| 编号 | 方法 | 路径 | 说明 |
|---|---|---|---|
| A01 | POST | `/api/app/auth/login` | 微信手机号授权登录/自动创建或绑定会员（按微信手机号登录扩展） |
| A02 | GET | `/api/app/auth/me` | 当前小程序账号 |
| A03 | POST | `/api/admin/auth/login` | 管理员登录 |
| A04 | GET | `/api/admin/auth/me` | 当前管理员信息 |
| A05 | POST | `/api/app/auth/phone-login` | 仅输入手机号登录/自动创建或复用会员，不验证号码归属 |

### A01 微信手机号授权登录

**请求**：`login_code`（必，`wx.login` 一次性凭证）、`phone_code`（必，微信手机号授权一次性凭证）。

```json
{"login_code":"微信登录凭证","phone_code":"微信手机号授权凭证"}
```

**返回 `data`**：`token`、`expires_in`（2592000 秒）、`member`（`id`,`phone`,`nickname`,`avatar`,`points`,`growth_points`）。

**规则**：请求携带微信 `login_code` 和手机号授权 `phone_code`；服务端向微信换取已授权手机号与当前小程序 OpenID，按手机号匹配或创建会员，并将 OpenID 安全绑定到该会员。已有未绑定会员沿用原会员 ID、订单和积分；已有绑定不一致或 OpenID 属于其他会员时返回 409，提示联系管理员，不自动换绑或合并。签发 30 天 JWT，不提供刷新 Token。详细行为以《微信手机号登录接口扩展》为准。

### A05 仅输入手机号登录

**请求**：`phone`（必，中国大陆手机号，字符串）。

```json
{"phone":"13800000000"}
```

**返回 `data`**：与 A01 相同，包含 `token`、`expires_in`（2592000 秒）和 `member`（`id`,`phone`,`nickname`,`avatar`,`points`,`growth_points`）。

**规则**：仅校验手机号格式，不验证号码归属，不调用微信接口；按手机号创建或复用会员，昵称设置为手机号后四位，头像设为默认头像，会员 ID、订单和积分保持关联。签发 30 天 JWT，不提供刷新 Token。知道他人手机号的人可能以该会员身份访问其会员数据及相关服务。

### A03 管理员登录

**请求**：`username`（必）、`password`（必）。**返回 `data`**：`token`、`admin`（`id`,`username`）。密码只验证哈希，不回传。

## 4. 模块二：客房与封房

| 编号 | 方法 | 路径 | 说明 |
|---|---|---|---|
| R01 | GET | `/api/app/rooms` | 房间列表/指定日期可订筛选 |
| R02 | GET | `/api/app/rooms/{id}` | 房间详情 |
| R03 | GET | `/api/app/rooms/{id}/availability` | 月度可订/不可订日期 |
| R04 | POST | `/api/app/rooms/availability-check` | 复核指定日期区间是否可订 |
| R05 | GET | `/api/admin/rooms` | 后台房间列表 |
| R06 | GET | `/api/admin/rooms/{id}` | 后台房间详情 |
| R07 | POST | `/api/admin/rooms` | 新增房间 |
| R08 | PUT | `/api/admin/rooms/{id}` | 编辑房间资料与价格 |
| R09 | PUT | `/api/admin/rooms/{id}/enabled` | 上架/下架房间 |
| R10 | GET | `/api/admin/room-blocks` | 封房列表 |
| R11 | POST | `/api/admin/room-blocks` | 新增封房 |
| R12 | PUT | `/api/admin/room-blocks/{id}` | 修改封房 |
| R13 | DELETE | `/api/admin/room-blocks/{id}` | 解除封房 |

### R01 房间列表

**查询**：`check_in`（选）、`check_out`（选）。两者须同时提供；不传则浏览全部已上架房间。

**返回 `data.list[]`**：`id`,`number`,`name`,`price`,`capacity`,`bed_info`,`images`（URL 数组）,`available`（传日期时）。只返回在整个住宿区间可订的房间（当提供日期时）。

### R03 查询月度不可订日期

**请求**：`GET /api/app/rooms/1/availability?month=2026-11`

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "room_id": 1,
    "month": "2026-11",
    "unavailable_dates": ["2026-11-20", "2026-11-21", "2026-11-25"]
  }
}
```

**规则**：合并有效 `orders`、`room_block`、`booking_lock` 的住宿夜晚并去重；返回范围仅限未来 60 个自然日，日期可由 `unavailable_dates` 是否包含映射为「不可预订」/「可预订」。超出 60 天范围的入住或退房日期在 R01、R04、P01 均拒绝；退房当天可作为新入住日；不向顾客暴露其他订单个人信息。选择连续多晚时须检查中间所有住宿夜晚。

### R04 指定日期区间复核

**请求**：`room_id`（必）、`check_in`（必）、`check_out`（必）。**返回**：`available`（布尔）、`nights`（整数）、`room_amount`（按当前房价计算的金额）。**规则**：仅用于展示/预检，不负责占房，必须校验入住、退房均在未来 60 天内，支付前必须重新事务校验。

### R07/R08 房间保存

**请求**：`number`,`name`,`floor`,`price`,`capacity`（必）；`bed_info`,`area`,`facilities`（JSON 数组）,`images`（图片 URL 数组）,`description`（选）。`enabled` 由 R09 单独维护。**返回**：房间详情。历史订单价格不随房价修改而变动。

### R09 上下架房间

**请求**：`enabled`（必，布尔）。**规则**：整间房是否展示/可售，与指定日期的管理员封房不同；不得作为历史订单状态。

### R10 封房列表

**查询**：`room_id`（选）、`month`（选）。**返回**：`id`,`room_id`,`start_date`,`end_date`,`reason`,`created_at`,`updated_at`。

### R11 新增封房

```json
{"room_id":1,"start_date":"2026-11-25","end_date":"2026-11-27","reason":"维修"}
```

**规则**：`end_date > start_date`；封房与有效订单、有效锁房冲突时返回 `409`；封房只记录管理员主动设置的不可订日期，**不传 `order_id`**。R12 更新沿用相同业务字段，R13 删除后自动恢复可订（前提是无其他占用）。

## 5. 模块三：订单管理

| 编号 | 方法 | 路径 | 说明 |
|---|---|---|---|
| O01 | GET | `/api/app/orders` | 我的订单列表 |
| O02 | GET | `/api/app/orders/{id}` | 我的订单详情 |
| O03 | GET | `/api/app/orders/{id}/cancel-eligibility` | 查询是否允许自助取消 |
| O04 | GET | `/api/admin/orders` | 后台订单列表 |
| O05 | GET | `/api/admin/orders/{id}` | 后台订单详情 |
| O06 | POST | `/api/admin/orders` | 手工新增第三方订单 |
| O07 | PUT | `/api/admin/orders/{id}` | 编辑订单允许的基本资料/房间日期（不含金额） |
| O08 | POST | `/api/admin/orders/{id}/confirm` | 确认订单 |
| O09 | POST | `/api/admin/orders/{id}/check-in` | 办理入住 |
| O10 | POST | `/api/admin/orders/{id}/check-out` | 办理退房 |
| O12 | POST | `/api/admin/orders/{id}/cancel` | 管理员取消待确认/待入住的第三方订单 |
| O13 | GET | `/api/admin/orders/export` | 导出全部订单及订单管理界面的全部字段（单工作表 XLSX） |

> 小程序正式订单由后端模拟支付成功后生成，**不提供普通的 `POST /api/app/orders`**。

### O01/O04 订单列表

**小程序查询**：`status`（选）、`page`,`size`。仅返回当前登录会员自己的订单。

**后台查询**：`channel_id`,`room_id`,`creator_id`,`status`,`check_in_from`,`check_in_to`,`guest_name`,`phone`,`keyword`,`without_creator`,`page`,`size`（均选）。`keyword` 匹配系统订单号、预订人或手机号；`without_creator=true` 筛选无达人订单。后台页面通过相同的 `check_in_from`、`check_in_to` 筛选指定入住日，页面默认每页 10 条，接口默认仍为 20 条。

**返回 `list[]`**：`id`,`order_no`,`room_id`,`room_number`,`channel_id`,`creator_id`,`guest_name`,`phone`,`check_in`,`check_out`,`nights`,`status`,`paid_amount`,`platform_fee`,`platform_commission`,`extra_commission`,`expected_amount`,`net_amount`。小程序响应应隐藏不必要的内部渠道提成信息。

### O13 后台订单 Excel 导出

**请求**：无筛选及分页参数。导出所有订单，按创建时间倒序排列，不受订单管理页面当前筛选和分页影响。响应为 `.xlsx` 文件，单个「订单管理」工作表；列包含订单列表及订单详情界面字段：订单及渠道/达人/客房标识与名称、联系人和住宿信息、全部金额快照、状态、第三方平台信息、会员标识、订单备注、管理员备注、预订人画像字段、系统创建和更新时间。缺失的可空字段留空，金额以十进制文本导出。

### O02 订单详情

**返回 `data`**：`id`,`order_no`,`room_id`,`room_number`,`guest_name`,`phone`,`guest_count`,`check_in`,`check_out`,`nights`,`status`,`remark`,`paid_amount`,`room_amount`,`points_used`,`discount_amount`,`created_at`,`updated_at`。金额均以十进制字符串返回。

其中 `points_used` 和 `discount_amount` 来自该订单的 `REDEEM` 积分流水；无积分抵扣时两者为 `0` 和 `"0.00"`。`room_amount` 为积分抵扣前房费，按 `paid_amount + discount_amount` 还原，保留订单创建时的金额口径；小程序按房费总额和住宿晚数展示每晚房价。

### O06 新增第三方订单

```json
{
  "channel_id": 2,
  "room_id": 1,
  "creator_id": null,
  "platform_order_no": null,
  "platform_order_date": "2026-11-18",
  "guest_name": "张先生",
  "phone": "13800000000",
  "guest_count": 2,
  "check_in": "2026-11-20",
  "check_out": "2026-11-22",
  "status": "PENDING_CONFIRM",
  "remark": "",
  "amount": {
    "paid_amount": "300.00",
    "platform_fee": "15.00",
    "platform_commission": "0.00",
    "expected_amount": null
  }
}
```

**必填**：`channel_id`,`room_id`,`check_in`,`check_out`,`status`,`amount.paid_amount`；其他字段选填，`platform_fee` 默认 0。**返回**：`id`,`order_no`,`net_amount`。

`platform_order_date` 为可空的第三方平台原始下单日期（YYYY-MM-DD）；后台录入表单默认北京时间当天，可清空。后台订单详情返回该字段，系统创建时间仍为 `created_at`。

**规则**：只允许六个外部渠道手工录入；`order_no` 系统生成；检查全住宿区间占用及平台订单号重复。无达人时两项达人提成强制 0；有达人时 `expected_amount` 必填且所属渠道匹配，后端自动计算 `extra_commission`；历史 `COMPLETED` 订单可直接录入并按手机号幂等发积分。

### O07 编辑订单

**请求**：`guest_name`,`phone`,`guest_count`,`remark`（选）；`room_id`,`check_in`,`check_out`（选，仅待确认/待入住）。实际入住人若启用 `order_guest`，通过关联资料更新。

**规则**：所有订单状态（含已取消）可编辑基本资料；只有待确认/待入住可更改房间或日期，且修改前后晚数必须一致，重新校验完整日期区间及封房；**所有状态均不允许传入或修改 `amount` 及任何金额、费用、预期收入字段**。修改住宿日期后，按新日期动态分摊跨月金额及费用。小程序顾客端不开放此接口。

### O08–O10 状态流转

| 接口 | 前置状态 | 目标状态 | 附加处理 |
|---|---|---|---|
| O08 确认 | `PENDING_CONFIRM` | `PENDING_CHECKIN` | 无 |
| O09 入住 | `PENDING_CHECKIN` | `CHECKED_IN` | 仅在北京时间预定入住日及之后；管理员手动操作 |
| O10 退房 | `CHECKED_IN` | `COMPLETED` | 仅在北京时间预定退房日及之后；管理员手动操作并触发一次性积分奖励 |

**返回**：`id`,`status`,`updated_at`。状态必须逐级前进，不可跳级/倒退；不自动入住、退房或取消。第三方创建时可直接选四种初始状态；小程序支付成功待确认且需管理员手动确认，不提供拒绝已支付订单接口。已完成订单不可通过普通接口取消。实际入住人登记若启用可选 `order_guest`，需另行确认接口，不在本期强制清单中。

### O12 管理员取消第三方订单

**请求**：`reason`（选）。**返回**：`id`,`status`（`CANCELLED`）。

**规则**：仅第三方来源且订单为待确认或待入住时可取消；成功后立即释放原定间夜；外部平台退款由原平台自行处理，本系统不生成微信退款记录。取消后不可恢复，原金额快照保留；录错金额时须取消并重新录入。

### O03 取消资格

**返回**：`eligible`（布尔）、`reason`（不可取消原因）、`deadline`（北京时间入住日 18:00）。**规则**：仅 `PENDING_CONFIRM`/`PENDING_CHECKIN` 且当前时间**严格早于**截止时刻才可自助申请退款；资格接口仅供展示，正式退款时必须再次校验。

**规则**：仅本人订单；状态为待确认/待入住，且当前北京时间严格早于入住当天 18:00；已入住/已完成不可普通取消。第一期由后端同步模拟退款成功，`refunds.amount=payments.amount`，写入成功流水（微信退款号为空），并在同一事务内将订单标记 `CANCELLED`、返还已使用积分、释放间夜；不发生真实资金流转。退款、取消、返积分必须幂等；处理失败则回滚，保持订单占用与积分不变。

| 编号 | 方法 | 路径 | 说明 |
|---|---|---|---|
| S01 | GET | `/api/admin/dashboard` | 当日房态与经营总览 |
| S02 | GET | `/api/admin/reports/overview` | 日/月整体经营报表 |
| S03 | GET | `/api/admin/reports/channels` | 按渠道统计 |
| S04 | GET | `/api/admin/reports/creators` | 按达人统计 |
| S05 | GET | `/api/admin/reports/rooms` | 按房间统计 |

### S01 经营总览

**查询**：`date`（选，默认北京时间今天）、`month`（选，默认当月）。

**返回**：`date`,`occupied_rooms`,`total_rooms`,`rooms[]`,`month_summary`。其中 `month_summary` 含 `unoccupied_order_revenue`（未入住订单营业额）、`checked_in_order_revenue`（已入住订单营业额）、`platform_fee`,`platform_commission`,`extra_commission`,`net_amount`,`expense_amount`,`operating_profit`,`occupancy_rate`。今日收入按当晚住宿归属，不按创建或收款日。

### S02 整体月度报表

**查询**：`month`（选，默认当前 `YYYY-MM`）、`scope`（选，默认 `ALL`，可选 `NOT_CHECKED_IN`、`CHECKED_IN`）。

**返回**：`month`,`scope`,`order_count`,`night_count`,`paid_amount`,`platform_fee`,`platform_commission`,`extra_commission`,`net_amount`,`unoccupied_order_revenue`,`checked_in_order_revenue`,`expense_amount`,`operating_profit`,`occupancy_rate`。

### S03–S05 分类月度报表

**查询**：均支持 `month`（默认当月）、`scope`（默认 `ALL`），并分别可选 `channel_id`、`creator_id`、`room_id`。

**返回 `list[]`**：`id`,`name`,`order_count`,`night_count`,`paid_amount`,`platform_fee`,`platform_commission`,`extra_commission`,`total_commission`,`net_amount`。S04 主播报表必须含 `creator_id=null` 的「无主播订单」行；S05 房间报表另返回 `room_profit`,`occupancy_rate`。

**统一统计规则**：

1. `ALL` = 除取消外全部有效订单；`NOT_CHECKED_IN` = 待确认+待入住；`CHECKED_IN` = 已入住+已完成。四维报表订单数、间夜数、营业额、三类费用、到手金额统一按 `scope` 筛选。
2. 订单数只归属入住日期所在月份；间夜及实付金额、三类费用按住宿夜晚所在月份平均分摊，分币尾差归**最后一晚**。订单日期在允许状态下修改后自动重算各月归属；金额不可修改。
3. `net_amount = paid_amount - platform_fee - platform_commission - extra_commission`；`total_commission = platform_commission + extra_commission`。小程序按积分抵扣后的模拟实付金额计收入。
4. `operating_profit` **始终**等于已入住订单当月到手金额减当月实际经营支出，不受 `scope` 改变；房间 `room_profit` 只减对应订单费用，不扣全店经营支出。
5. `occupancy_rate = checked_in_nights / (calendar_nights - manually_blocked_nights)`；总览以六间房间夜汇总，房间报表按单房计算。分子只含已入住/已完成订单间夜，已入住订单未来间夜也计入对应月份；无预订占用率。分母为零时返回 `null`，不做除零。
6. 已取消订单不计入；第一期模拟支付金额仅为业务测试口径，不代表真实资金到账；微信支付手续费不记录、不统计、不扣减。

## 14. 实施注意及尚未确定事项

1. **已统一**：需求、数据库、接口均不提供订单金额修改、支出编辑/删除、第一期导出备份、通用审计日志。外部订单取消与微信退款属于不同流程。
2. 有主播时 `expected_amount` 必填，`extra_commission=max(0, paid_amount-platform_fee-platform_commission-expected_amount)` 自动计算；无主播默认两项主播提成为零。
3. 第三方平台补贴/实际结算差额如何入账尚未定义；当前以录入的顾客实付金额统计。
4. 第三方订单仅允许管理员手动录入；无平台订单号时由管理员核对重复记录，日期冲突由管理员处理后重试，系统不得绕过占房校验。
5. 实际入住人表 `order_guest` 可选；若启用，需补充登记/编辑接口及数据保护措施。
6. 第一期无微信支付通知与退款回调；模拟支付、10 分钟锁房超时关闭、模拟退款、积分幂等均须 MySQL 事务与并发控制；过期锁房不得继续支付或强制超售。
7. 接口路径及统一响应为第一期拟定契约；真实微信支付、付款人 OpenID 校验、支付回调与关单接口留待后续版本。OpenID 仅用于 A01 微信授权登录身份绑定。
