# 携程酒店基础信息与点评的合规批量获取调研

调研日期：2026-11-22  
适用问题：能否批量获取携程（Trip.com Group）酒店基本信息及酒店点评。

> 本文基于携程/Trip.com 官方公开资料，记录技术与授权边界，不构成法律意见。接口字段、可访问数据和商业授权均应以双方最终签订的协议及账号权限为准。

## 结论

**可以在获得携程/Trip.com 书面授权或成为其签约合作方后批量对接部分酒店数据；不能把公开网页当作可自由、全量抓取的商业数据源。**

- 官方 Partner API 存在“酒店可售性查询”能力，且一个请求最多可查询 **20 个已知 HotelID**。该接口需要携程提供的合作方账号/密钥信息，并不是匿名公开 API；它适合在已知酒店集合上批量查询可售性、房型和价格等实时数据，不等同于可下载全站酒店目录。
- Trip.com Connectivity 的公开介绍列出酒店、房型、价格计划、图片及“点评信息、状态查询”等住宿连接能力；但这只是面向签约住宿连接合作方的能力概述。**它不能证明任意酒店评论正文可由普通开发者公开批量导出，也不能证明我方可以获得、存储或二次展示该等评论。** 评论接口、字段、权限范围和商业使用权必须在签约时由携程书面确认。
- 如果目标是**自有或已签约管理的酒店**，官方 eBooking 商户后台提供酒店信息维护和点评管理，是最直接的合规入口。若需程序化同步，应向携程申请对应的 Connectivity/API 权限。
- 携程平台用户服务协议明确禁止未经事先书面同意，以网络爬虫、复制、传播等方式获取并商业性利用平台展示资料。因此，不建议通过爬虫、逆向网页接口、账号池或绕过访问限制的方式批量采集酒店和点评数据。

## 官方资料能确认的能力与边界

| 场景 | 可确认事项 | 不能据此推断的事项 |
| --- | --- | --- |
| 已知酒店的批量实时查询 | Trip Partner API 的 `HotelIDs` 参数每次最多 20 家；请求还需 `AllianceID`、`SID`、签名等合作方凭据。 | 可匿名调用；可枚举或下载全站酒店基础资料；可取得点评全文。 |
| 酒店供应/渠道管理集成 | Trip.com Connectivity 面向 PMS、渠道管理、CRS 等住宿连接合作方；公开介绍列出酒店、房型、价格计划、图片、点评信息等内容能力。 | 非签约方可访问；可获得任意/竞争酒店或全平台所有评论；评论可二次展示或转售。 |
| 自有酒店点评运营 | eBooking 明确提供酒店信息维护和点评管理。 | 可以导出所有携程酒店数据或他人酒店的完整评论库。 |

### 重要的授权限制

携程现行用户服务协议规定，未经携程事先书面同意，不得将平台数据作商业性利用，也不得自行、协助或授权第三方以网络爬虫、复制、传播等方式获取、使用平台展示资料；协议还规定平台内容（包括文字、图片、数据、信息等）的知识产权归携程所有，除书面同意或另有约定外不得使用或制作衍生作品。

因此，即便网页上可以看到酒店名称、地址、评分和评论，也不自动形成批量采集、长期存储、向客户展示或再分发的授权。`robots.txt` 也不能替代合同或书面授权。

## 点评数据的特别结论

携程官方点评规则说明，点评来自真实订单，并包含评分、文字、图片、视频等内容；这类内容同时可能涉及著作权、个人信息和平台使用规则。**本次查到的官方公开资料没有证明：普通开发者可通过公开 API 批量导出任意酒店的评论全文。** 这不等于签约合作方绝无此能力，而是意味着在拿到携程的书面授权、接口文档和测试账号前，不能把它列为可交付能力。

若业务确实需要评论，应在合作协议或数据授权中逐项写明：

1. 是否仅限本酒店/本集团，还是可覆盖指定城市、品牌或全量酒店；
2. 可获取字段：评分、评论正文、图片/视频、入住日期、房型、标签、商家回复、作者展示名等；
3. 是否允许存储、展示、搜索、训练模型、做情感分析、再授权或再分发；
4. 历史评论回溯深度、增量更新机制、接口频率和错误重试规则；
5. 脱敏标准、保留期限、删除/下架同步、数据安全与审计责任。

在未经明确授权前，建议只保存经许可的聚合指标（例如评分和评论数），不要落库评论全文、用户昵称、图片或视频。

## 建议的落地路径

### 路径 A：管理自有/签约酒店（推荐）

1. 通过携程 eBooking/市场经理确认房源归属及商户账号。
2. 向携程申请 Connectivity 或 Partner API，并书面确认允许同步的字段和点评范围。
3. 以携程 HotelID 做唯一外部标识；先用少量酒店做联调和数据验收，再按合同约定的分页、频率和增量方式同步。
4. 将来源、授权版本、抓取/同步时间、删除状态和原始 HotelID 写入审计字段，避免把携程数据和自有数据混淆。

### 路径 B：做市场研究、竞品库或全网酒店目录

先向携程/Trip.com 商务或数据合作渠道申请数据授权、API 或数据许可。询价/沟通时应直接说明用途、酒店覆盖范围、字段清单、更新频率、是否展示评论全文、是否用于模型训练及是否向第三方提供服务。未获书面许可前，不应开始批量抓取或上线基于该数据的功能。

## 向携程确认的最小问题清单

可向 `ebooking@trip.com`（中国大陆商户咨询）或对应市场经理确认：

1. 是否可为本业务开通 Hotel Content / Review 的 API 或数据导出权限；
2. 接口是否只覆盖我方管理的酒店，还是支持指定酒店清单；
3. 是否返回点评正文、图片/视频、商家回复和评论者展示信息；
4. 允许的存储、缓存、展示、分析及删除同步规则；
5. 认证方式、沙箱、QPS、批量上限、价格及 SLA；
6. 是否需要另签数据使用或个人信息处理协议。

3. [携程 eBooking 酒店商户端](https://ebooking.ctrip.com/) —— 官方商户后台，说明酒店信息维护与点评管理，并公布中国大陆商户咨询邮箱。
4. [携程平台用户服务协议](https://rulecenter.ctrip.com/statics/rule/72/latest.html) —— 用户行为规范和知识产权条款；重点参见第 5、6 节。
5. [携程酒店点评规则](https://m.ctrip.com/webapp/hotel/integralrule) —— 说明点评与真实订单、评分、文字、图片、视频及展示规则的关系。
