# 微信手机号授权登录需求扩展

本扩展更新 V3.1 中小程序会员“直接输入手机号登录”的规定。其他订单、积分和模拟支付规则继续沿用 V3.1。

## 登录流程

- 登录页只提供微信手机号授权登录，不提供直接输入手机号作为认证手段。
- 用户同意后，小程序获取 `wx.login` 登录凭证和 `getPhoneNumber` 手机号授权凭证并提交后端。前端不得自行提交手机号或 OpenID 作为身份依据。
- 服务端分别向微信换取当前小程序 OpenID 和授权手机号；校验成功后按手机号匹配会员，绑定该 OpenID，再签发 30 天会员 JWT。
- 新手机号创建会员。已有手机号会员且 OpenID 为空时，复用原会员 ID 并写入 OpenID；原有订单、积分、余额及其他会员资料保持关联。
- 手机号与 OpenID 已绑定到同一会员时允许幂等登录。
- 手机号已有不同 OpenID，或当前 OpenID 已属于其他会员时，返回冲突并提示“账号绑定信息存在冲突，请联系管理员处理”。不自动换绑、合并账号或签发令牌。
- 用户拒绝手机号授权、凭证无效或微信服务不可用时，不创建会员、不签发令牌；可重新发起登录。
- 管理员预建会员的 OpenID 保持为空，待该会员首次成功微信授权登录时绑定。无需数据库回填或迁移。

## 安全与兼容

- 微信凭证兑换在数据库事务外进行；会员查找、创建及绑定在同一数据库事务内执行，并使用手机号/OpenID 唯一约束处理并发。
- 不记录登录 code、手机号、OpenID、session key 或 access token。
- 登录接口从 `{phone}` 改为 `{login_code, phone_code}`。旧客户端不再兼容，发布后需要升级小程序并重新登录。
- 通过会员 JWT 认证版本使改造前已签发的会员令牌失效；管理员令牌不受影响。
- 微信手机号授权能力、AppID 和 AppSecret 必须在上线前完成平台及服务端配置。OpenID 仅属于当前小程序，不作为跨小程序全局身份。

## 验收场景

- 新手机号第一次授权创建唯一会员并保存 OpenID。
- 已有同手机号且无 OpenID 的会员首次授权后沿用原 ID；既有订单和积分保持不变。
- 同一手机号和 OpenID 重复登录成功且不重复创建会员。
- 手机号绑定不同 OpenID、OpenID 属于另一会员、拒绝授权、无效 code、微信错误和并发首次登录均不发生错误账号绑定或发放令牌。
- 旧手机号请求不能登录；旧会员 JWT 返回未认证；新会员 JWT 正常，管理员 JWT 不受影响。
