# 芊浔民宿需求扩展 V3.2：微信支付

发布日期：2026-11-20（Asia/Shanghai）

## 版本关系

本文记录经用户确认的真实微信支付扩展。除本文明确覆盖的支付和退款规则外，继续遵循 V3.1。真实微信支付启用是部署环境配置，不在小程序或后台提供商户开关。

## 支付模式

- `WECHAT_PAY_ENABLED=false`（默认）：新支付交易只走模拟支付，不发生资金流转。
- `WECHAT_PAY_ENABLED=true`：新支付交易只走微信小程序支付；`mock-pay` 接口拒绝请求。
- 支付方式在创建支付流水时固化。切换配置不改变既有流水的方式；关闭微信开关后，微信回调仍须处理既有微信交易。
- 微信模式在服务端配置 AppID、AppSecret、商户号、商户证书序列号、APIv3 密钥、商户私钥路径、支付和退款回调 URL。不得将密钥放入小程序。

## 会员身份绑定

- 会员登录时提供 `wx.login` 与手机号授权一次性凭证，服务端向微信换取 OpenID 与已验证手机号；仅凭输入手机号不再允许登录。
- 已有同手机号会员复用原记录并绑定 OpenID，包括管理员预建会员；不存在时创建会员，保留已有订单及积分。
- 一个会员只能绑定一个 OpenID，一个 OpenID 只能绑定一个会员。已绑定其他会员或会员已有其他 OpenID 时拒绝支付。
- 不允许仅凭用户提交的手机号或小程序客户端字段信任 OpenID。支付前换取当前 OpenID 并核对已绑定身份，不再重复授权手机号。旧会员 JWT 失效并重新登录；已绑定其他微信账号时联系管理员线下核实，不自动换绑。

## 支付与退款状态

- 服务器创建微信 JSAPI 预支付单后，小程序可调用 `wx.requestPayment`。客户端成功回调不是付款凭证；订单、支付流水、积分扣除只由验签成功的服务端支付通知结算。
- 微信支付通知核验 AppID、商户号、商户单号、付款人、金额、状态及锁房有效期；重复通知幂等。
- 过期锁房在释放房间和积分预占前，先请求微信关闭交易并核对微信侧结果。微信状态不明确时保留预占并等待后续扫描对账。
- 微信整笔退款以稳定商户退款单号调用微信 API。微信返回处理中时本地保持 `PENDING`；仅微信退款成功通知/查询确认后，在同一数据库事务内写成功流水、取消订单并返还已抵扣积分。
- 退款失败不取消订单、不返还积分；重复退款和重复通知保持幂等。

## 联调边界

本地默认不开启。真实支付需要已认证商户配置、微信小程序合法域名及可公网访问的 HTTPS 支付/退款回调；没有这些条件时只验证模拟支付和本地代码行为。
