# 芊浔民宿微信小程序及管理后台需求规格说明书

> 版本：V1.4（2026-11-17）  
> 适用范围：第一期产品需求与后续数据库、接口、UI、测试设计

## 1. 项目概述

芊浔民宿位于浙江省湖州市南浔区，单店经营，共六间房：一楼 101、102、103；二楼 201、202、203。建设微信小程序供顾客直接预订并支付，建设 PC 管理后台统一管理小程序及第三方平台订单、房态、会员积分、达人费用和经营报表。

**第一期原则**：以预订与管理闭环、数据准确和低维护成本为优先；不做多门店、复杂营销、动态定价及第三方平台自动对接。

### 1.1 用户角色

- **顾客/会员**：通过微信小程序手机号登录、查询客房、预订支付、取消退款、查询订单、使用积分。
- **管理员**：单个后台账号；管理房间、订单、入住退房、会员积分、平台达人、经营支出与报表。

### 1.2 系统组成

微信小程序、PC 管理后台、统一后端服务及统一数据库。小程序支付成功后的订单自动进入后台，不需要二次录入。

## 2. 统一术语与订单来源

### 2.1 术语

| 名称 | 定义 |
|---|---|
| 注册账号 | 顾客登录小程序的账号 |
| 注册手机号 | 注册账号绑定且经过验证的手机号，自动积分归属依据 |
| 预订人 | 预订页面填写的联系人姓名 |
| 手机号码/预订手机号 | 预订页面填写的联系人电话，允许与注册手机号不同 |
| 入住人数 | 计划入住人数 |
| 入住人 | 实际办理入住的人员，可与预订人不同 |
| 实付金额 | 顾客实际付款金额，第三方订单必填，积分奖励计算依据 |
| 净营业额 | 实付金额减去平台手续费、平台达人提成、达人额外提成 |
| 微信实付金额 | 小程序订单通过微信实际支付金额 |
| 已核收入 | 已办理入住订单对应的内部经营确认收入，不等同银行到账或会计收入 |
| 待核收入 | 尚未办理入住订单对应的预计收入 |
| 间夜 | 一间客房实际住宿一个夜晚 |

**禁止混用注册手机号、预订手机号和入住人手机号。** 小程序订单自动积分发放给下单注册账号，而非预订人或入住人。

| 美团 | MEITUAN | 管理员手动录入 |

| 同程 | TONGCHENG | 管理员手动录入 |

## 3. 微信小程序需求（七个模块）

### 3.1 手机号登录、首页与房间查询

- 顾客通过微信小程序手机号登录；注册账号绑定经过验证的手机号。具体授权方式、首次登录授权文案与异常处理在 UI/API 设计时细化。

- 首页展示品牌信息和预订卡片：**入住日期、退房日期、共几晚、查询按钮**。
- 退房日期必须晚于入住日期；不允许选择过去的入住日期；自动计算晚数。
- 查询整个住宿区间内可订房间；有效订单、管理员封房及有效支付临时占用均不可重复预订。
- 支持不选日期直接浏览全部房间；不做复杂筛选、排序和入住人数搜索。
- 查询结果逐间展示房间缩略图、房间名称、床型等基本信息、可入住人数、每晚价格及「查看详情」按钮。查询结果必须满足整个所选住宿区间可订。

### 3.2 房间详情与可订日历

- 展示房间号、房型、楼层、图片、面积、床型、可入住人数、设施、介绍及每晚价格。
- 房间详情展示底部「立即预订」按钮，点击后进入入住日期选择日历。
- 日历仅允许选中可预订日期；已有有效订单、有效临时锁房或管理员封房覆盖的住宿夜晚均不可选。其他平台订单须先由管理员录入系统才能反映为不可订。
- 修改日期重新计算晚数和费用，确认入住及退房日期后进入预订填写页。
- 每间房第一期仅一个基础房价；不做周末、节假日和动态定价。
- 房价变更仅影响新订单，历史订单保存价格快照。

### 3.3 预订与微信支付

预订填写页字段**统一命名**如下：

| 字段 | 必填 | 说明 |
|---|---|---|
| 预订人 | 是 | 联系人姓名，不等同于注册账号或实际入住人 |
| 手机号码 | 是 | 预订联系人电话 |
| 入住人数 | 是 | 不超过客房容量 |
| 备注 | 否 | 特殊需求 |

不要求预订页面填写身份证号码；实际住宿登记信息可由管理员依法按需补充。

- 预订填写页顶部展示房间缩略图、房间名称、入住/退房日期及住宿晚数；表单字段为预订人、手机号码、入住人数、备注。
- 费用展示：每晚房价及晚数（如各晚价格不同应列明明细）、房费原价/总价、使用积分数量、积分抵扣金额、微信实付金额；微信实付 = 房费原价 − 积分抵扣。
- 页面底部显示「立即支付」按钮，发起微信支付。
- 下单时后端再次校验库存、价格、会员积分；创建**临时支付交易**并短时间锁定对应间夜。
- **只有支付成功且经后端核实后才创建正式订单**，初始状态「待确认」，自动出现在 PC 后台。
- 支付失败、取消或超时不创建正式订单；临时占用到期释放。
- 处理支付回调重复、延迟、异常和并发抢房；不得仅依赖前端支付成功提示。
- 第一阶段一笔订单只预订一间房，不做多房间合单。
- 支付成功且后端核实后进入「预订成功」结果页，显示「查看订单」「返回首页」两个按钮；支付未核实成功时不可错误展示预订成功。

### 3.4 我的订单与退款

正式订单状态：**待确认、待入住、已入住、已完成、已取消**。不设置可见的正式「待支付」订单。

- 我的订单页面提供六个筛选标签：全部、待确认、待入住、已入住、已完成、已取消。
- 列表展示订单号、房间、入住日期、住宿晚数、实付金额、状态。
- 点击订单进入详情：顶部展示订单状态；订单信息包括订单号、房间、入住日期、退房日期、住宿晚数、入住人数、预订人、手机号码、备注；费用明细展示每晚房价 × 晚数（或逐晚明细）、房费总价、使用积分数、积分抵扣金额、实付金额。
- **待确认或待入住**订单，且当前时间**严格早于入住当天 18:00（北京时间）**，允许顾客自助取消并申请退款。
- 当天 18:00 起不支持普通自助退款；18:00 之后新下单也没有额外宽限期。
- 已入住、已完成订单不提供普通退款入口；重复扣款、商家无法履约或依法需要处理的情况走异常处理。
- 微信退款按原支付渠道处理；退款状态、流水、失败原因独立保存，订单原始金额不修改。
- 取消订单须处理已抵扣积分的退回，并以可靠状态和幂等逻辑避免重复退款、重复返积分。
- 第一期不支持已付款订单修改房间、入住日期、退房日期和金额；符合退款条件时可取消后重订。
- 订单详情底部展示「申请退款」入口：符合自助退款条件时可操作；不符合时显示灰色不可直接提交退款的样式，点击提示「当前订单不支持自助退款，请联系商家」，并展示商家联系电话。前后端均必须重新校验资格；异常退款仍按专门流程处理。

### 3.5 会员与积分

#### 会员等级

| 等级 | 累计获得积分门槛 |
|---|---:|
| 普通会员 | 0–499 |
| 银卡会员 | 500–999 |
| 金卡会员 | 1000–1499 |
| 钻石会员 | ≥1500 |

新注册用户为普通会员。等级依据累计成长积分判定，消费可用积分不降低等级；积分不设有效期。

#### 自动发放

- 小程序订单变为「已完成」（办理退房）后，按**微信实际支付金额每满 ¥1 发 1 积分**；小数金额建议向下取整。
- **积分归属订单关联的小程序注册账号**，由账号确定绑定手机号；不以预订人/入住人手机号匹配。
- 一笔订单正常自动奖励仅发一次；失败记录原因，支持安全重试；需要唯一约束或幂等标识。
- **第三方订单仅在「已完成」且有有效预订手机号时自动创建或关联会员，并按实付金额每满 ¥1 奖励 1 积分**（不足 ¥1 不计）。未完成订单不因订单导入而创建会员或发积分。
- 导入时已经是「已完成」的历史第三方订单，导入成功后立即执行上述会员创建与积分奖励；没有手机号的订单可正常导入但不创建会员或发积分。
- 同一手机号会员去重、同一订单积分仅发一次；发放时保存金额和积分流水快照。订单事后修改金额、费用或状态，不追回、不重算、不重复发放已奖励积分。

#### 管理员手动发放

- 管理员输入**会员手机号**查询账号，填写发放积分数量并确认，即可发放；建议提供可选备注/原因及关联订单。
- 会员管理支持独立新增会员、批量导入会员、录入初始积分；不要求会员已经登录小程序。顾客以后通过相同手机号完成验证登录后关联既有会员。
- 记录管理员、手机号对应会员、数量、时间、原因、关联订单、变动前后余额，防止重复提交。
- **建议**区分「历史消费补发」（计入累计成长积分）与「赠送/补偿」（仅增加可用积分）；此项尚待最终确认。

#### 积分抵扣

- 单笔订单抵扣上限为**房费的 20%**；同时不得超过可用积分可兑换金额。
- **已确认兑换率**：普通会员 30 积分抵扣 ¥1、银卡会员 25 积分抵扣 ¥1、金卡会员 20 积分抵扣 ¥1、钻石会员 15 积分抵扣 ¥1。
- 订单取消退款时恢复已实际扣除的积分；支付失败或临时交易超时释放预占积分。
- 积分流水包括订单奖励、人工发放、抵扣、返还、异常调整，记录来源及关联业务。

### 3.6 会员中心（已确认独立页面）

- 需要独立会员中心页面，展示当前会员等级、累计成长积分、可用积分、距离下一等级所需成长积分及升级进度；钻石等级显示已达最高等级。
- 展示四个等级的成长积分门槛及**已确认**的积分兑换比例；展示积分获取、抵扣上限、取消订单返还、积分无有效期等规则。
- 提供「积分流水」入口，支持查看积分获取、使用、返还及管理员发放记录，展示时间、变动积分和来源。
- 不新增优先入住、专属客服、活动通知、优惠券等未经确认的会员权益。
- **导航位置待确认**：会员中心是底部独立导航入口，还是由「我的」页面进入，尚未最终决定。

### 3.7 个人中心

展示微信头像、微信昵称、会员等级、累计成长积分、可用积分、我的订单、会员中心入口、积分流水、民宿地址与联系电话；个人资料页面保持简洁。

## 4. PC 管理后台需求（九个模块）

### 4.1 经营总览（可切换月份）

- 支持切换月份查看经营数据；当日客房占用与所选月份经营指标应明确标注时间口径。展示实付金额、平台手续费、平台达人提成、达人额外提成、净营业额等。
- 六间房状态卡片展示房号、房态、预订人、入住人数、入住/退房日期、订单来源；点击进入订单。
- **今日住宿收入按今天对应的住宿夜晚归属**，不是按今日创建订单或今日收款计算。
- 已核与待核须分开，实际到账/结算也应与经营收入分开。

### 4.2 月度房态日历

六种正式房态：

| 房态 | 业务含义 |
|---|---|
| 空房 | 当晚可预订 |
| 已预订 | 已支付，管理员尚未确认（订单待确认） |
| 待入住 | 管理员已确认 |
| 已入住 | 已办理入住 |
| 已退房 | 已办理退房（订单已完成） |
| 不可预订 | 管理员封房 |

**展示规则（已确认）：**

- 六间房为行、日期为列，每个住宿夜晚一个格子。
- **入住日期格子显示完整订单状态**；连住的后续夜晚显示「占用」，仅为视觉标记，**不是第七种正式房态**。
- 退房日期不占用当晚，可显示空房或该晚新订单状态。
- 办理退房后，原入住日期格子显示「已退房」，续住夜晚仍显示「占用」作为历史记录。
- 点击入住日状态或续住「占用」格子均可查看同一笔订单。
- 例如 11/17 入住、11/20 退房：17 日「已入住」、18–19 日「占用」、20 日「空房」；退房后 17 日改为「已退房」。
- 后端始终按整个 `[入住日期, 退房日期)` 区间判断冲突，不依据格子文案判断。
- 支持切换月份、查看来源和封房记录。
- **点击空房格子可新增第三方订单**：自动带入房间号、入住日期，退房日期默认次日；住多晚时可修改退房日期。提交时重新检查完整日期区间的房态冲突。

### 4.3 订单管理

- 七种来源统一管理，支持来源、房间、状态、日期、预订人、手机号筛选；第三方订单支持单笔录入和 CSV/Excel 批量导入。
- 订单管理新增时手动选择房间和入住/退房日期；从房态日历点击空房格子新增时自动带入房间号和入住日期，退房日期默认次日且可修改；两种入口复用同一订单创建逻辑。
- 小程序订单支付成功自动入后台，初始「待确认」，依次流转为「待入住」「已入住」「已完成」；第三方订单录入时可选择实际订单状态，包括「已完成」的历史订单。
- **第三方订单字段如下**：

| 字段 | 要求 |
|---|---|
| 订单来源 | 必填：抖音、美团、携程、同程、飞猪、途家 |
| 房间号、入住日期、退房日期 | 必填；日历入口自动带入房号、入住日，退房日默认次日 |
| 订单状态 | 必填；允许直接导入历史已完成订单 |
| **实付金额** | **必填；顾客实际支付金额** |
| 平台手续费 | 选填，默认 0 |
| 平台达人提成 | 选填，默认 0 |
| 达人额外提成 | 选填，默认 0 |
| **净营业额** | 自动计算，不手填 |
| 预订人、手机号、入住人数、备注 | 选填；手机号用于完成订单的会员积分 |
| 平台订单号、关联达人 | 选填；建议提供平台订单号防重 |

- **不再要求输入订单原始房费，也不强制填写平台实际结算金额。**
- **净营业额 = 实付金额 − 平台手续费 − 平台达人提成 − 达人额外提成**。避免同一费用重复扣除。
- 管理员可以修改订单实付金额及三类费用；修改后经营总览、订单列表、按日/月、平台、达人、房间等所有相关统计均以最新有效金额重新计算，记录修改前后数值、操作人和时间。
- **已发积分不追回、不补发、不重新计算**；同一订单不能因修改或重复导入而再次发积分。
- 导入前校验日期、金额、房态冲突及重复订单；优先以来源+平台订单号防重，无订单号时提示疑似重复。
- 小程序订单的微信支付、退款流水与第三方订单金额录入相互独立；不因此开放小程序顾客自助改价、改期或换房。

### 4.4 客房管理

- 管理六间房的房号、名称、楼层、图片、面积、床型、人数、设施、介绍和基础价格。
- 支持指定日期范围封房；与有效订单冲突时拒绝直接封房并提示先处理订单。
- 调整价格不追溯影响已有订单。

### 4.5 会员管理

- 后台统一设置「会员管理」，不再另设独立顾客管理菜单；实际入住人登记仍可保留在订单关联资料中。
- 支持按手机号查询、单独新增会员、批量导入会员、设置初始积分、查看等级、成长积分、可用积分、消费订单及积分流水。
- **管理员可直接创建从未登录过微信小程序的会员**；该顾客以后通过同一手机号验证登录时关联已有会员并查看积分。按手机号去重，不重复创建。
- 第三方订单中预订人和手机号均为选填。只有订单已完成且手机号有效时，自动创建或关联会员并按**实付金额每满 ¥1 发 1 积分**；历史已完成订单导入成功后立即处理。未完成订单不自动建会员、不发积分。
- 小程序订单奖励仍归属于下单时已验证的注册账号，不能仅按预订手机号发给其他人。
- 支持管理员手动赠送积分，记录来源、操作人、时间、关联订单和余额变动；人工初始积分是否计入成长积分见待确认事项。
- 同一订单仅奖励一次；发放时记录当时实付金额和积分数，后续金额变更不追回或重算积分。

### 4.6 平台与达人管理

- 固定七种订单来源；支持按平台统计订单数、间夜、顾客实付、手续费、佣金及净营业额。
- 达人资料包括名称、所属平台及关联订单；统计达人订单数、间夜数、成交额、平台达人提成和额外达人提成。
- 外部订单金额区分：实付金额、平台手续费、平台达人提成、达人额外提成、净营业额；平台实际结算金额不作为第一期强制录入项。
- **不得重复扣除已包含在平台费用中的达人佣金。** 平台实际结算以平台账单为准，可能存在平台补贴或优惠差异。
- 小程序订单记录房费、积分抵扣、微信实付；不要求人工填写第三方平台手续费或达人佣金。微信支付可能有商户手续费，第一期可暂不逐笔人工录入。

### 4.7 经营支出管理

- CRUD：新增、查询、编辑、删除、统计。
- 字段：ID、支出内容（自由填写）、支出金额、支出日期、创建时间、更新时间。
- 不强制支出类型；房租、水电、采购、人工、维修等自行填写。
- 与订单独立记录，但纳入经营利润。

### 4.8 经营报表

支持整体、按平台、按达人、按房间、按日、按月统计：订单数、间夜数、已核营业额、待核营业额、平台手续费、达人提成、净营业额、经营支出、经营利润。

- **按住宿夜晚归属收入**：11/17 入住、11/19 退房，¥200/晚，17 日和 18 日各计 ¥200，19 日不计。
- **跨月分摊**：11/30 入住、12/2 退房，共 ¥400，则 11 月 ¥200、12 月 ¥200。
- 平台手续费及达人提成按住宿夜晚合理分摊；订单办理入住后内部状态整体转已核，但每晚仍按日期归属。
- **净营业额 = 有效房费收入 − 平台手续费 − 平台达人提成 − 达人额外提成**。
- **经营利润 = 净营业额 − 经营支出**；第一期不强制把公共费用分摊到房间。
- 小程序积分抵扣减少顾客实际支付，报表须区分房费原价、抵扣与实付；避免把积分抵扣当成现金收入。
- 退款、优惠、平台补贴和异常调整须保留独立记录，不通过覆盖历史订单金额处理。

### 4.9 系统设置

第一期设置页面仅提供数据导出及备份功能：支持按业务表导出 CSV，建议打包 ZIP。图片等非表格资料需另行打包才构成完整备份。不展示民宿名称/地址/电话、管理员资料、修改密码或其他配置入口。后台仍需在服务端安全配置支付参数。

## 5. 核心流程

### 5.1 小程序订单

注册登录 → 查询房间 → 选择日期与房间 → 填写**预订人/手机号码/入住人数/备注** → 选择积分抵扣 → 确认费用 → 临时锁房并发起微信支付 → 后端确认支付成功 → 正式订单自动入后台（待确认）→ 管理员确认（待入住）→ 办理入住（已入住）→ 办理退房（已完成）→ **向下单注册账号发放积分**。

### 5.2 外部订单

第三方平台产生订单 → 管理员从订单管理或房态日历录入（也可批量导入）→ 校验房态和重复订单 → 按实际状态创建订单 → 办理入住、退房 → **订单已完成且有有效手机号时自动创建/关联会员并按实付金额发积分**。历史已完成订单导入成功后立即执行该流程。

### 5.3 取消退款

顾客打开待确认/待入住订单 → 校验北京时间入住当日 18:00 截止 → 申请取消退款 → 记录取消/退款状态 → 原渠道退款 → 返还已使用积分 → 更新库存与流水；异常或失败须可追踪、可重试且不得重复执行。

### 5.4 手动积分发放

管理员进入会员管理 → 按手机号查询、单独创建或批量导入会员 → 设置初始积分或手动赠送积分 → 确认 → 记录积分流水、操作人、原因和时间。

## 6. 核心数据对象与设计约束

| 对象 | 作用 |
|---|---|
| 注册账号 | 微信登录身份、验证手机号 |
| 会员 | 等级、累计成长积分、可用积分 |
| 房间 | 基础资料、价格 |
| 封房记录 | 不可订日期区间 |
| 正式订单 | 七种渠道统一订单、状态、注册账号关联、预订人快照 |
| 订单间夜明细 | 每晚价格、收入归属及跨月分摊 |
| 临时支付交易 | 预支付锁房及超时控制 |
| 支付记录 | 微信支付交易与回调 |
| 退款记录 | 退款状态、流水、原因 |
| 入住人/订单入住人 | 实际住宿登记，区别于预订人 |
| 积分流水 | 自动发放、手动发放、抵扣、返还及调整 |
| 积分发放任务 | 失败原因、重试、幂等 |
| 订单来源 | 七种固定渠道 |
| 达人 | 所属平台及佣金关联 |
| 经营支出 | 内容、金额、支出日期 |
| 管理员/操作日志 | 单账号管理及关键变更审计 |

**关键约束：**

1. 预订区间采用 `[入住日, 退房日)`，退房当晚可售。
2. 防止同一房间同一住宿夜晚出现两笔有效订单或有效锁房冲突。
3. 支付回调、退款、积分发放、人工积分发放均需幂等处理。
4. 第三方订单金额允许更正；经营统计以最新有效金额为准，关键变更保留操作日志；积分发放时另存不可被后续改价覆盖的快照。
5. 注册账号、预订联系人和实际入住人是不同业务实体。
6. 外部订单不生成虚假的微信支付流水。
7. 重要操作留痕；敏感手机号、住宿登记信息依法保护；数据库定期备份。

## 7. 第一阶段明确不开发

第三方平台 API 自动同步；已付款订单改期/换房/补差价；多房间合单；多门店；多管理员复杂权限；周末/节假日/动态价格；复杂优惠券、拼团、满减；积分过期；未完成外部订单自动创建会员；已完成订单普通退款；完整财务会计系统；员工排班和库存系统。

## 8. 开发顺序

1. **房间与订单基础**：房间、价格、封房、统一订单、手动录入、状态流转、房态日历。
2. **小程序预订支付**：注册登录、查询、详情、预订表单、微信支付、自动入后台、退款。
3. **会员积分**：等级、自动发放、手机号手动发放、抵扣、流水、失败重试。
4. **经营管理与报表**：平台达人、支出、今日总览、跨月间夜统计、净营业额和利润。

财务快照、间夜明细、支付退款和积分流水的数据结构必须在前期规划，避免后续返工。

## 9. 验收标准

- [ ] 六间房均可管理、查询、预订，日期冲突被阻止。
- [ ] 小程序支付成功自动生成一笔后台正式订单；支付失败不生成。
- [ ] 六种外部来源可手动录入或批量导入，可直接录入已完成的历史订单。
- [ ] 订单状态按待确认→待入住→已入住→已完成流转。
- [ ] 房态日历显示六种正式房态，连住后续夜晚显示「占用」，退房当晚可售。
- [ ] 预订表单仅要求预订人、手机号码、入住人数，备注可选。
- [ ] 退款严格执行待确认/待入住且入住当日 18:00 前的规则。
- [ ] 小程序自动积分归属**下单注册账号**，即使预订手机号不同也不会发错。
- [ ] 管理员可单独或批量创建未登录小程序的会员，支持初始积分与手动赠送。
- [ ] 第三方订单已完成且有手机号时自动建会员并发积分；历史已完成订单导入后立即处理。
- [ ] 管理员可通过手机号查询会员并手动发放积分，留存流水。
- [ ] 同一订单自动积分不重复，失败可重试。
- [ ] 等级门槛为 500/1000/1500，积分抵扣上限 20%；兑换率分别为 30/25/20/15 积分抵扣 ¥1。
- [ ] 手机号登录后可查询房间、查看详情、选择可订日期并完成预订。
- [ ] 微信支付核实成功后展示预订成功页，含查看订单与返回首页入口。
- [ ] 我的订单支持六种状态筛选，订单详情完整展示联系人、住宿及积分抵扣明细。
- [ ] 不符合自助退款条件时按钮呈灰色，点击显示联系商家提示及联系电话。
- [ ] 独立会员中心展示等级、升级进度、可用积分、积分规则和积分流水。
- [ ] 第三方订单金额仅「实付金额」必填，净营业额由三类费用自动扣除计算。
- [ ] 房态日历空房格子快捷新增订单，房号和入住日自动带入、退房日默认次日。
- [ ] 修改费用后全部相关报表按最新金额重算，已发积分不追回、不重算。
- [ ] 每日收入按住宿夜晚归属，跨月正确拆分。
- [ ] 经营支出独立记录，并纳入经营利润。

## 10. 待最终确认事项

1. **会员中心导航位置**：独立会员中心页面已确认需要，底部导航是否单列「会员」仍待确认。
2. **人工积分与升级关系**：建议历史消费补发计入累计成长积分，赠送/补偿仅增加可用余额；待确认。
3. **外部平台补贴/商家优惠**：出现顾客实付与平台结算不一致时，需要明确补贴承担方及收入归属。
4. **异常退款**：已完成订单不提供普通退款入口，但需要保留依法退款和支付差错处理能力。
5. **支付手续费对账**：微信支付商户手续费第一期可不逐笔人工录入，后续对账完善。
6. **人工外部订单重复录入**：优先以平台+平台订单号防重，缺失订单号时的判重细节待明确。
7. **已完成订单改为已取消**：已发积分遵循不追回原则；取消后的财务收入与退款流水如何处理仍需确认。
8. **跨月费用分摊**：第三方订单仅录入总实付金额，建议按住宿夜晚均摊及处理分币尾差，具体规则待确认。
