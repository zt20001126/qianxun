# 芊浔民宿数据库扩展 V3.3：顾客画像

> 新增 V11、V12、V13 迁移，不修改已应用迁移。画像功能最终新增两张表：`booker_profile` 和 `portrait_tag`。

## 1. 订单字段

- `orders.admin_remark VARCHAR(500) NULL`：该笔订单的管理员备注。
- `orders.remark` 继续保存该笔订单的用户下单备注。画像页按手机号汇总所有关联订单的 `remark`；数据仍以订单行作为来源，避免重复存储和双向同步。

## 2. 画像主表：booker_profile

一手机号一行；`phone` 非空时有唯一索引。手机号为空时以唯一 `order_id` 关联单笔订单。画像字段：

- `guest_name`、`phone`：联系人显示字段；姓名变化不改变画像身份。
- `age`、`party_type`、`inferred_region`：可持续编辑的画像属性；地区可手工填写，也可由浏览器本地推算。
- `tags JSON`：当前画像已选标签名称数组，允许持续编辑。
- `admin_remark VARCHAR(2000)`：手机号级、可持续编辑的管理员备注。
- `identity_key`：手机号的 SHA-256 键；手机号为空时由订单主键生成。
- `order_id`：无手机号画像的订单兜底关联。

群体编码为 `SOLO`、`COUPLE`、`PARENT_CHILD`、`FAMILY_FRIENDS`、`FRIENDS`、`BUSINESS`、`GROUP`、`OTHER`。

画像与订单通过 `orders.phone` 匹配；无手机号时使用 `booker_profile.order_id`。不使用独立画像订单关联表。

## 3. 标签选项表：portrait_tag

保存系统预置（古镇游览、自驾、晚到、亲子设施、长住、复住）和管理员新增的可复用标签名称。画像所选标签不使用关联表，而以名称数组保存在 `booker_profile.tags`。V13 将历史标签回填到画像 JSON，并确保历史标签仍作为可选项保留；同时写入预置标签。

## 4. 迁移收敛

V13 迁移后画像功能只保留 `booker_profile` 与 `portrait_tag` 两张表；删除旧的 `booker_profile_order` 与 `booker_profile_tag`，不删除标签字典。迁移合并重复手机号画像、保留画像资料和标签，给无手机号画像补 `order_id`，并为手机号及订单兜底键添加唯一约束。

## 5. 统计口径

- 订单备注汇总：按手机号查询所有关联订单的 `orders.remark`，按订单逐笔提供编辑。
- 累计订单数：`orders.status = 'COMPLETED'` 的订单数。
- 累计消费：对应 `order_amount.paid_amount` 合计。
- 管理端会员显示按手机号匹配 `members.phone`；不改变积分归属。
